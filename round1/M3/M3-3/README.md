# M3-3 ｜ 自主导航与调优：从"能规划"到"能到达"

> **难度**：★★★
> **综合考察**：Nav2 架构、代价地图、全局/局部规划、参数调优方法论
> **本题分值权重**：30
> **题目来源**：`创意组一轮考核.md` §M3-3
> **形式**：Gazebo 仿真（自带阿克曼小车 + M3-2 的地图）；现场带配置与文档实测

---

## 0. 这道题在考什么

有了地图（M3-2）不等于能导航。Nav2 是一整套系统：**规划器、控制器、代价地图、
行为树、恢复行为**——任何一环配错，车就卡住、撞墙或原地打转。

本题考的是**工程调优能力**，具体三点：

1. 你**理解 Nav2 的数据流**（谁给谁喂数据、谁决定速度）
2. 你会**用指标驱动调参**（不是"试到能跑为止"）
3. 你说得清**每个参数改了会怎样**、以及**代价是什么**

> **你的是阿克曼车，不能原地转**。这一点会直接影响规划器与控制器选型，
> 用差速车的默认配置必然失败——**这是本题第一个坑**。

## 2. 任务分解

### 2.1 选型：阿克曼车能用什么（第一个坑）

阿克曼转向有**最小转弯半径**，规划出来的路径必须**曲率连续且可行**。
差速车常用的组合（如 NavFn + DWB 默认参数）在阿克曼车上会表现为：
车在转弯处卡住、反复前后挪、或直接撞墙。

| 环节 | 可用方案 | 说明 |
| :-- | :-- | :-- |
| **全局规划** | `SmacPlannerHybrid`（Hybrid-A*） | **推荐**：直接支持非完整约束，输出可跟随的平滑路径 |
| | `NavFn` / `SmacPlanner2D` | 输出的是"栅格路径"，阿克曼车跟随困难，需自己处理 |
| **局部控制** | `MPPI`（`nav2_mppi_controller`） | **推荐**：可配阿克曼运动模型 |
| | `TEB`（`teb_local_planner`） | 支持 car-like 约束，是经典选择 |
| | `RPP`（Regulated Pure Pursuit） | 轻量；对曲率有限制，需调 `max_curvature` |

**文档里要写清**：你选了什么、为什么、以及**换成另一种会怎样**（可基于实测）。

> **你的车实际接口**（从 `smart_car.urdf.xacro` 提取）：
> 用 `gazebo_ros2_control` + `ackermann_steering_controller`，
> 订阅 **`cmd_vel`**（`geometry_msgs/Twist`），发布 **`odom`** 与 **`/tf`**。
>
> 也就是说：**Nav2 输出的 `Twist` 会被控制器换算成前后轮的转向角与转速**。
> 你需要说清：
> - **轴距（0.28 m）与轮距（0.18 m）** 在控制器配置里的位置
> - 控制器参数文件 `ackermann_controllers.yaml` **已随 M3-1 提供**，
>   你要**读懂它**并核对以下三组值**是否与 URDF 一致**：
>
> | 参数 | `ackermann_controllers.yaml` | `smart_car.urdf.xacro` |
> | :-- | :-- | :-- |
> | `wheelbase` | 0.28 | `wheelbase` = 0.28 |
> | 轮半径 | 0.05 | `wheel_radius` = 0.05 |
> | 转向限位 | ±0.5236 | `lower/upper` = ∓0.5236 |
> | 轮距 | 0.18 | `traction_track_width` = 0.18 |
>
> **这几组值必须一致**——不一致会表现为"车走了 1 m，`/odom` 只显示 0.9 m"，
> 而且**很难查**（因为两边看起来都"能跑"）。这正是本题想让你建立的意识：
> **改了 URDF 的几何，就要同步改控制器参数。**
>
> 另外注意 `base_frame_id: base_footprint`——URDF 里 `base_footprint` 与
> `base_link` 之间是一个 **fixed joint**，高度差 = `wheel_radius` = **0.05 m**
> （即 `base_footprint` 在地面，`base_link` 在轮轴高度）。
> **说清为什么需要这一层**（提示：与 RSSI/导航的"地面投影"有什么关系）。

### 2.2 让定位跑起来

导航需要 `map → odom → base_link` 全链路。两种做法：

| 做法 | 说明 |
| :-- | :-- |
| **AMCL**（推荐） | 用 M3-2 的地图 + 激光做粒子滤波定位 |
| 直接发静态 `map→odom` | 仅当仿真真值与地图完全对齐时可行；**必须在文档里说明这是简化** |

要求：给出 `map → odom` 的**来源**（谁发布、依据什么），并说明它和 M3-1 的区别。

### 2.3 配置 Nav2

产出 `nav2_params.yaml`，**每个非默认参数都要有注释**说明为什么改。

必须正确配置的几处（常见翻车点）：

| 项 | 要点 |
| :-- | :-- |
| 机器人外形 | `robot_radius` 或 `footprint`（阿克曼车**不是圆形**，用多边形更准） |
| 激光话题 | `scan` 的 topic 名与 `frame_id` 要对上 |
| 代价地图层 | `obstacle_layer` / `inflation_layer`；**膨胀半径**是关键（见下） |
| 速度限制 | `max_vel_x` / `max_vel_theta` / `min_vel_x`；阿克曼车**不能倒着规划**，`min_vel_x` 要注意 |
| 目标容差 | `xy_goal_tolerance` / `yaw_goal_tolerance`（太小会永远"差一点"） |

**膨胀半径（`inflation_radius`）**是本题最值得调的参数之一：

- 太小 → 车贴着墙走，转弯时刮蹭
- 太大 → 窄门被完全堵死，规划不出路径

> 你的 M3-2 地图里有窄门。**膨胀半径与窄门宽度的关系**是必答项。

### 2.5 可视化与诊断

必须提供：

- **代价地图截图**（全局 + 局部），能看出障碍膨胀区
- **规划路径截图**（全局路径 + 局部实际轨迹）
- **`/cmd_vel` 或角速度曲线**（说明控制是否平滑）

## 5. 交付物与格式

```
M3-3/
├── config/
│   ├── nav2_params.yaml          # 带注释（每个改动都说明理由）
│   └── amcl_params.yaml          # 若用 AMCL
├── launch/
│   └── bringup.launch.py         # 一键启动：仿真 + 定位 + Nav2
├── scripts/
│   ├── goto.py                   # 发目标点并统计结果（可批量跑）
│   └── eval_run.py               # 从 rosbag/日志算成功率与耗时
├── results/
│   ├── tuning_log.md             # 参数调优记录表
│   ├── runs.md                   # 3 次运行结果 + 失败归因
│   └── *.png                     # 代价地图 / 路径 / cmd_vel 曲线
└── README.md                     # 一键复现
```

### 运行约定

```bash
# 一键起全栈（必须单命令）
ros2 launch <你的包> bringup.launch.py map:=<M3-2 的 map.yaml> use_sim_time:=true

# 发目标点并统计
python3 scripts/goto.py --x 5.0 --y 2.0 --runs 3 --out results/
```

## 6. 常见追问（提前想清楚）

1. 你为什么选这个**全局规划器**？它和 NavFn 输出的路径有什么本质区别？
2. 阿克曼车为什么不能用差速车的默认配置？**具体会在哪一步失败**？
3. **膨胀半径**你设了多少？和窄门宽度的关系是什么？调大一倍会怎样？
4. 你的 `footprint` 是圆还是多边形？用圆的误差在哪？
5. 局部代价地图**清除障碍**的机制是怎样的？如果动态障碍消失了，地图多久更新？
6. `xy_goal_tolerance` 设得太小会发生什么？
7. 失败的那次，**根因在哪一层**（定位？规划？控制？代价地图？）怎么定位的？
8. `map → odom` 是谁发的？如果 AMCL 丢定位，导航会怎样？
9. 行为树里有哪些**恢复行为**？你实测触发过吗？
10. 如果要求成功率 ≥95%，你会先改什么？代价是什么？

## 7. 明确禁止

- 禁止用差速车的默认配置直接交（阿克曼必须给出适配依据）
- 禁止只报"调了 3 个参数"而没有前后数据
- 禁止只跑成功的那几次（**失败必须记录**）
- 禁止把目标点写死在代码里（现场会换目标点）
- 禁止直接用 `/gazebo/model_states` 喂给 Nav2 当定位（绕过定位模块 = 作弊）
- 禁止拿 M3-2 之外的地图
