# M3-2 ｜ SLAM 建图：让地图"能用来导航"

> **难度**：★★
> **综合考察**：SLAM 原理、激光数据特性、地图质量评估、回环与漂移修正
> **本题分值权重**：20
> **题目来源**：`创意组一轮考核.md` §M3-2
> **形式**：Gazebo 仿真（自带阿克曼小车 + 雷达），学生**自建世界**；现场带地图与文档实测

---

## 0. 这道题在考什么

SLAM 的产出是一张地图，但**"看起来像地图"和"能用来导航"是两回事**。

一张能用的地图必须：

1. **墙是直的**（不是弯的、不是双影的）—— 这考验你的 SLAM 是否收敛
2. **闭环处不能有鬼影**—— 同一面墙只出现一次，这考验回环检测
3. **分辨率与占据阈值合理**—— 太粗导航会撞墙，太细文件巨大且噪声多

本题的场景是**你自己搭的**，所以你必须同时成为"出题人"和"解题人"：
设计一个**能暴露 SLAM 问题**的场景，再用 SLAM 把它建出来。

> **关键**：场景里必须有**回环**。没有回环的走廊，任何 SLAM 都能建得像样，
> 考不出真实能力。

## 1. 硬性要求

| # | 要求 | 说明 |
| :-- | :-- | :-- |
| 1 | **世界必须含三要素** | 长走廊 + **至少一个回环路径** + 一个**自定难点**（见 §2.1） |
| 2 | **必须用激光 SLAM** | `slam_toolbox` 或 `cartographer`（任选）；不接受"手写栅格拼接" |
| 3 | **输出标准格式** | `map.pgm` + `map.yaml`（ROS 地图标准，能被 `map_server` 加载） |
| 4 | **必须经过回环** | 轨迹要绕回已建图区域，触发回环闭合 |
| 5 | **给出质量证据** | 墙直不直、闭环有无鬼影，都要有**图 + 数据**支撑 |

> 场景自建，但**不许用官方示例世界**（`turtlebot3_world` 之类）。
> 难点必须你自己设计，并在文档里说明"这个难点想考什么"。

## 2. 任务分解

### 2.1 设计世界（考你自己）

世界（`.world` 文件）必须包含：

| 要素 | 要求 | 为什么 |
| :-- | :-- | :-- |
| **长走廊** | 长度 ≥8 m，宽度 1.5~2.5 m | 走廊是里程计漂移最容易暴露的地方（无特征可修正） |
| **回环路径** | 走完一圈能回到已建图区域 | **触发回环检测**，这是 SLAM 的核心能力 |
| **自定难点** | 至少 1 个，自己设计 | 例如：细窄通道 / 玻璃（雷达穿透）/ 空旷大厅（特征少）/ 陡角 |

**文档里要写清**：你的难点是什么、预期它会引发什么问题、实际是否如预期。

> 好的难点示例："一段 1 m 宽的窄门，两侧墙体会让雷达产生多次反射，
> 预期在地图上留下伪影。"
> 差的难点："我加了个障碍物。"——障碍物不构成难点。

### 2.2 跑 SLAM

任选一种 SLAM 方案，记录完整配置：

| 方案 | 关键参数举例 |
| :-- | :-- |
| `slam_toolbox` | `resolution` / `max_laser_range` / `minimum_travel_distance` / `loop_search_maximum_distance` |
| `cartographer` | `TRAJECTORY_BUILDER_2D.*` / `POSE_GRAPH.optimize_every_n_nodes` |

要求：

- **配置以 YAML 形式提交**，不许用默认参数直接跑（默认参数下要说明"为什么默认就够"）
- 地图分辨率（`resolution`）要**说出选择依据**（房间尺寸？导航精度需求？）

**你的雷达实际参数**（从 `smart_car.urdf.xacro` 提取，配置时按这个来）：

| 项 | 值 |
| :-- | :-- |
| 话题 | `/scan`（`sensor_msgs/LaserScan`） |
| `frame_id` | `lidar_link` |
| 线数 | 360（`-180° ~ +180°`） |
| 更新率 | 10 Hz |
| `range_min` / `range_max` | 0.12 m / 8.0 m |
| 测距噪声 | 高斯，`stddev = 0.01 m` |
| 角分辨率 | 1° |

> 两个**必须想清楚**的点：
> 1. **`max_laser_range` 不要超过 8.0 m**（设大了会引入无效点，地图出现伪影）
> 2. **10 Hz 的更新率**决定了你的巡场速度上限——走太快，两次扫描之间位移过大，
>    建图会"撕开"。先算一下：`0.3 m/s ÷ 10 Hz = 3 cm/帧`，这个间距相对
>    0.05 m 的分辨率是否够密？

### 2.3 控制车走完全程

可以用键盘遥控，但**推荐用脚本**（可复现）：

- 轨迹必须**覆盖整个场景**，特别是回环段
- 转弯速度**不要太快**（阿克曼转角大时激光会甩动，导致地图扭曲）
- 建议速度：直线 `0.2~0.3 m/s`，转弯 `0.1~0.15 m/s`

**记录**：`/odom`、`/scan`、`tf`（至少录 rosbag，便于复盘）。

### 2.4 质量评估（本题的核心）

建完图**不能只看一眼说"挺好"**。至少给出三组证据：

**① 墙的直线度**

在走廊区域取一面墙，测它在图上是否为直线：

```
方法举例：沿墙取 N 个点，拟合直线，计算最大偏差（像素/米）
```

**② 回环一致性（关键）**

找到被走过两次的同一面墙，检查它在图上：

- 是**一条线**（回环成功）
- 还是**两条平行的线**（回环失败 / 漂移未修正）

给出**定量结果**（如"两次经过的墙间距 = 0.12 m"）。

**③ 地图可用性**

说明这张图是否满足 M3-3 的导航需求：

- 分辨率是否足够（窄门宽度 ≥ 3 个栅格）
- 是否有"伪障碍"（本该空旷处出现黑点）
- 边界是否封闭（导航时车不会"看到"地图外的虚空）

### 2.5 对比实验（选做，建议做）

同一场景，**改一个关键参数**再建一次，对比差异。例如：

- `resolution`：0.05 → 0.025（地图大小 vs 精度）
- `loop_search_maximum_distance`：开/关回环（**最能说明回环的价值**）
- 走快 vs 走慢（速度对地图扭曲的影响）

给出**两张地图 + 数据对比表**。

## 3. 现场流程（约 12 分钟）

| 环节 | 内容 | 时间 |
| :-- | :-- | :--: |
| 看世界 | 确认三要素齐全，难点合理 | 3 min |
| 看地图 | 加载 `map.pgm`，检查墙直度与鬼影 | 3 min |
| 定量证据 | 三组质量数据（墙直度 / 回环间距 / 可用性） | 4 min |
| 追问 | 参数依据、难点是否如愿、漂移从哪来 | 2 min |

## 4. 交付物与格式

```
M3-2/
├── worlds/scene.world            # 自建世界（含三要素）
├── config/
│   └── slam_params.yaml          # SLAM 配置（含注释说明每个改动）
├── maps/
│   ├── map.pgm                   # 建图结果
│   ├── map.yaml
│   └── map_with_loop_off.pgm     # 若做了对比实验
├── bags/                          # 原始 rosbag（可给链接）
├── scripts/
│   ├── drive_route.py            # 可复现的巡场脚本
│   └── eval_map.py               # 质量评估（墙直度/回环间距）
├── results/
│   ├── quality_report.md         # 三组证据 + 对比表
│   └── *.png                     # 地图截图、评估图
└── README.md                     # 一键复现步骤
```

### `map.yaml` 关键字段

```yaml
image: map.pgm
resolution: 0.05          # 米/像素，说出选择依据
origin: [-10.0, -10.0, 0.0]
negate: 0
occupied_thresh: 0.65
free_thresh: 0.196
```

## 5. 明确禁止

- 禁止使用官方示例世界（必须自建，且含回环）
- 禁止用 `/gazebo/model_states` 当真值去**修正**地图（作弊；SLAM 只允许用 `/scan` + `/odom`）
- 禁止只交地图不给质量证据（"看起来像"不算）
- 禁止直接跑默认参数且说不清每个参数的作用
- 禁止把难点写成"我加了个箱子"（那不叫难点）
