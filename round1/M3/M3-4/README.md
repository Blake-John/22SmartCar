# M3-4 ｜ 动态障碍下的局部规划与避障：从"能到达"到"到得了且不被拦"

> **难度**：★★★★
> **综合考察**：局部规划器原理、动态障碍处理、多方案对比评测、失效分析
> **本题分值权重**：40
> **题目来源**：`创意组一轮考核.md` §M3-4
> **形式**：Gazebo 仿真（自带阿克曼小车 + M3-2 地图 + M3-3 导航栈）；现场实测

---

## 0. 这道题在考什么

静态地图上的导航（M3-3）是"开卷考试"——障碍物位置早就标好了。
真实赛场不是：**障碍物会动、会在你出发后才出现**。

本题考四件事，**层层递进**：

1. **注入机制**：你能不能在仿真里可靠地造出"临时障碍"
2. **对比评测**：两种局部规划器，用**四个量化指标**比出高下
3. **调优改造**：把差的那个调好，说清每一步为什么
4. **失效分析**：**说清你的方案在什么条件下会失败**——这是本题最高分项

> 本题**不追求 100% 成功率**。真实场景下局部规划器一定会有失效边界，
> **能准确说出边界在哪**比"成功率好看"更有价值。

| # | 要求 | 说明 |
| :-- | :-- | :-- |
| 1 | **障碍物必须在导航开始后出现** | 不许在起点就摆好（那是静态避障，不是本题） |

## 2. 任务分解

### 2.1 障碍物注入机制

在 M3-2 已建好的地图上，**导航开始后**增加临时障碍。可选做法：

| 做法 | 说明 | 优缺点 |
| :-- | :-- | :-- |
| **Gazebo 动态模型**（推荐） | 用 `gazebo_ros` 的 spawn/delete service 在指定时刻生成障碍模型 | 最真实：雷达能扫到、物理会碰撞 |
| 移动模型 | 障碍物沿固定路径运动（匀速或往返） | 能测"动目标"场景，难度更高 |
| 局部代价地图注入 | 直接往 `/local_costmap/costmap` 写障碍 | 简单但**雷达看不到**，不算真避障 |

**要求**：

- 注入位置：**在规划路径上**（否则车根本不会遇到，测不出东西）
- 注入时机：车出发后 **2~4 秒**（给车进入运动状态的余地）
- **脚本化**：一个命令就能重现同一场景

```
推荐参数化：
  --obstacle-at 3.0,1.5      # 障碍物世界坐标（放在路径中段）
  --delay 3.0                # 出发后多少秒出现
  --obstacle-size 0.6        # 障碍物边长（与窄门宽度挂钩）
```

> **难度设计**：障碍物尺寸至少要**明显大于膨胀半径**，否则车会"蹭过去"，
> 测不出避障能力。建议 0.5~0.8 m。

### 2.2 对比评测（本题核心）

选 **2 种**局部规划器：

**方式 A**：两种不同规划器。阿克曼车可选：

| 规划器 | 特点 |
| :-- | :-- |
| `MPPI` (`nav2_mppi_controller`) | 采样式，可配阿克曼模型；参数多、上限高 |
| `TEB` (`teb_local_planner`) | 优化式，支持 car-like 约束；经典但对参数敏感 |
| `RPP` (`nav2_regulated_pure_pursuit_controller`) | 轻量，对曲率有限制 |

**方式 B**：同一种规划器的**两套极端参数**（如保守 vs 激进）。必须说明这两套参数的差异是什么。

**四个指标**（缺一不可）：

| 指标 | 定义 | 怎么测 |
| :-- | :-- | :-- |
| **避障成功率** | 10 次尝试中成功到达几次 | 目标点相同、障碍物脚本相同 |
| **平均导航耗时** | 从接收目标到到达的平均秒数（只算成功的） | 记录每次的起止时间 |
| **绕行额外路径** | 实际路径长度 − 无障碍时的路径长度（米） | 从 `/plan` 或实际轨迹积分路径长度 |
| **路径平滑度** | 单位距离内**转向角变化总量**（rad/m） | 对轨迹求曲率或航向角差分，除以路程 |

> **平滑度**对阿克曼车尤其重要：转向角剧烈变化意味着车在"画龙"，
> 实车上会表现为抖动、轮胎磨损、乘客不适。

**记录要求**：每种规划器 × 10 次 = **20 次运行**，每次都要有数据行。

### 2.3 参数调优

挑**表现较差**的那一种，做针对性调优。要求：

- 明确说出**差在哪**（成功率低？绕太远？不平滑？）
- 每次只改**少数几个**参数（不要一次全改，否则归因不清）
- 记录表格：

| 轮次 | 改了哪个参数 | 默认值 | 新值 | 为什么这么改 | 成功率 | 平均耗时 | 绕行 | 平滑度 |
| :--: | :-- | :-- | :-- | :-- | :--: | :--: | :--: | :--: |
| 1 | | | | | | | | |
| 2 | | | | | | | | |

**调优后必须重跑 10 次**（不能只跑 1 次说"好了"）。

### 2.4 可视化

必须提供：

- **避开障碍的过程截图序列**（≥4 帧：接近 → 检测到 → 绕行 → 通过）
- **两种规划器的轨迹对比图**（同一坐标系叠加）
- **指标对比柱状图**（四个指标各一组）

### 2.5 分析报告（最高分项）

必须回答以下四问，**每问都要引用你自己的实测数据**：

**① 哪种局部规划器综合表现更好？为什么？**

> 不要只说"X 更好"，要指出**在哪个指标上更好、代价是什么**。
> 例："MPPI 成功率高 20%，但平均耗时多 3.2 s，因为它更保守。"

**② 你的局部规划器在什么情况下会失效？**

这是**本题最重要的答案**。请给出你的实测边界，例如：

- 障碍物出现得**太靠近起点**（车还没加速就要绕）
- 障碍物**移动太快**（超过局部规划器的预测能力）
- 障碍物**太靠近墙**（可通行空间小于车宽 + 2×膨胀半径）
- **窄门 + 障碍物同时出现**（无解场景）

**每一条都要有触发实验**：什么参数下必失败，给出数据。

**③ 局部规划器失效时，全局规划器有没有触发重规划？延迟多少？**

- 怎么观测的（哪个话题/日志）
- 重规划的**延迟**（从判定失败到出新路径的时间）
- 重规划后能否脱困

**④ 针对你的比赛场景，你会选哪种？参数怎么设？**

- 场景是你自己定义的（写清是什么场景、有什么约束）
- 给出**具体参数值**和选择理由

## 3. 现场流程（约 20 分钟）

| 环节 | 内容 | 时间 |
| :-- | :-- | :--: |
| 注入演示 | 现场跑一次：车出发后障碍物出现，看避障过程 | 4 min |
| **随机障碍** | 考官**随机指定**位置放障碍，跑 2 次（每目标点 2 次机会，可调参） | 8 min |
| 看对比数据 | 两种规划器的 20 次数据 + 四指标对比图 | 4 min |
| 失效分析 | 追问失效边界，要求现场复现一条 | 4 min |

> **现场随机性**：考官会挑一个**你没预置过**的位置放障碍。
> 这检验你的方案是"真的能避障"还是"针对固定脚本调出来的"。

## 4. 交付物与格式

```
M3-4/
├── scripts/
│   ├── inject_obstacle.py        # 导航中注入障碍（参数化）
│   ├── run_benchmark.py          # 跑 N 次并采集四指标
│   └── eval_metrics.py           # 从轨迹算绕行长度与平滑度
├── config/
│   ├── planner_a_params.yaml     # 规划器 A（或参数方案 A）
│   ├── planner_b_params.yaml     # 规划器 B
│   └── planner_b_tuned.yaml      # 调优后
├── results/
│   ├── benchmark.csv             # 2×10 次原始数据
│   ├── tuning_log.md             # 逐轮调优记录
│   ├── failure_boundary.md       # 失效边界与触发实验
│   └── *.png                     # 过程截图 / 轨迹对比 / 指标柱状图
├── report.md                     # 分析报告（四问）
└── README.md                     # 一键复现
```

### 运行约定

```bash
# 基准测试（2 种规划器 × 10 次）
python3 scripts/run_benchmark.py --planners A,B --runs 10 \
    --obstacle-at 3.0,1.5 --delay 3.0 --out results/

# 现场随机障碍
python3 scripts/run_benchmark.py --planners A --runs 2 \
    --obstacle-at <考官指定> --delay 2.5
```

## 5. 明确禁止

- 禁止在起点就摆好障碍物（必须是导航开始后出现）
- 禁止只跑 1 次就报成功率（**必须 10 次**）
- 禁止只报成功的次数、隐瞒失败原因
- 禁止直接往代价地图写障碍而绕过雷达（不算真避障）
- 禁止把障碍位置/时机写死（现场考官会随机指定）
- 禁止缺"平滑度"指标（这是最容易漏的一项）
- 禁止调优时一次改一堆参数导致无法归因
