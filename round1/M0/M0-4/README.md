## 场景

比赛时，车要按顺序做多个任务（比如先巡线、再避障、最后停车）。

你需要写一个**命令行下的任务调度模拟器**，把"**任务状态管理**"和"**时间监控**"抽象成代码。

**不依赖任何 ROS 或 GUI，全在终端运行。**

---

## 任务

实现一个名为 **`TaskScheduler`** 的 Python 程序，满足以下需求。

### 1. 配置加载

读取一个 `tasks.yaml`（或 `tasks.json`）文件，里面定义了 **5~8 个任务**。每个任务包含：

```yaml
timeout: 15          # 可选，全局超时（秒）

tasks:
  - name: "Navigate"         # 任务名（唯一）
    duration: 2.5            # 预期耗时（秒）
    success_rate: 0.8        # 模拟成功率 0~1
    dependencies: ["Init"]   # 依赖的前置任务列表
```

本目录提供 `tasks_demo.yaml` 与 `tasks_demo.json`（内容等价）作为示例。

### 2. 核心调度逻辑

- **按依赖顺序执行任务（拓扑排序）**
  - 必须正确处理**分叉 / 汇合**（一个任务被多个任务依赖；一个任务依赖多个前置）
  - 必须能检测**依赖环**并报错
- 每个任务模拟执行时，根据 `success_rate` **随机判定成功或失败**
- 如果任务失败，**最多重试 2 次**（即最多共 3 次尝试）
  - 若仍失败则**跳过该任务**（记录为 `SKIPPED`）
  - 并**继续执行后续不依赖它**的任务
  - 依赖它的下游任务也应被标记为 `SKIPPED`（而不是"成功"）
- **时间会计**：
  - 程序运行开始时记录真实时间
  - 每执行一个任务，`sleep(duration)` 模拟耗时，并累加总耗时
  - 如果总耗时超过用户设定的 `--timeout 15`（秒），**立即终止所有任务**并输出 `TIMEOUT`

### 3. 日志与输出

- **控制台必须实时彩色输出**：

  | 状态 | 颜色 |
  | :-- | :-- |
  | `SUCCESS` | 绿色 |
  | `FAILED` | 红色 |
  | `RETRY` | 黄色 |
  | `SKIPPED` | 蓝色 |

- 程序运行结束后，生成一个 `report.yaml` 或 **`report.json`**，包含：
  - 每个任务的**最终状态**
  - **总耗时**
  - **是否超时**

### 4. 工程规范（综合考察）

- **必须使用虚拟环境**（证明你会用 M0-1 装的环境）
- 提供 **`requirements.txt`**
- 必须写**完整的 `README.md`**，包含：
  - **参数说明**
  - **3 个运行示例**

## 现场验收

现场会给你**一份全新的 `tasks.yaml` / `tasks.json`**。
按下列方式调用你的程序：

```bash
python3 scheduler.py --config tasks.yaml \
    --timeout 15 --report report.json --seed 42
```

参数要求：

| 参数 | 必填 | 说明 |
| :-- | :--: | :-- |
| `--config <path>` | **是** | 任务配置文件（`.yaml` / `.yml` / `.json`） |
| `--timeout <float>` | 否 | 覆盖配置文件中的 `timeout` |
| `--report <path>` | 否 | 报告输出路径，默认 `report.json` |
| `--seed <int>` | 否 | 随机种子，便于**复现**同一结果（强烈建议支持） |

**`report.json` 的结构**（现场会按此结构核对）：

```json
{
  "timeout": false,
  "total_duration": 11.01,
  "tasks": [
    {
      "name": "Init",
      "status": "SUCCESS",
      "attempts": 1,
      "duration": 0.5,
      "started_at": 1699999999.12,
      "ended_at": 1699999999.62
    }
  ]
}
```

- `status` 取值必须是：`SUCCESS` / `FAILED` / `SKIPPED` / `TIMEOUT`
- `attempts` 为整数，**不得超过 3**
- `tasks` 中必须**包含配置文件里的每一个任务**（包括被跳过的和超时未执行的）

**异常输入**（依赖成环、依赖不存在的任务、空任务列表、`success_rate` 越界、
YAML/JSON 语法错误、文件不存在）必须**给出可读错误提示并以非 0 退出**，
**不允许抛出栈回溯**。

## 设计提示

- **先想清楚"依赖失败"的传播规则**：
  一个任务的前置是 `SKIPPED`，它自己应该是什么？这个规则要想透再写。
- **超时判定**放在哪里很关键：
  - 执行**前**检查一次
  - 每个任务 `sleep` **之后**再检查一次
  - 否则最后一个任务可能"睡过了头"才被发现
- **`--seed` 会让你的调试轻松很多**：不要每次跑都得到不同的随机结果。
- 彩色输出**注意在非 TTY 环境降级**（否则重定向到文件时全是乱码转义符）。
