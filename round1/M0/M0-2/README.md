## 你拿到的"祖传"代码

本目录提供：

| 文件 | 说明 |
| :-- | :-- |
| `legacy_corr.py` | 祖传 Python 脚本，**写得很烂**，功能是算两列数据的相关系数 |
| `config.yaml` | 示例配置：指定输入 csv 与参与计算的两列 |
| `sample_data.csv` | 示例数据（含`timestamp` / `sensor_a` / `sensor_b` / `note` 四列） |

**脚本的功能**：读取 yaml 配置 → 读取 csv 数据 → 计算两列数据的相关系数 → 打印结果。

**它存在的问题**（我们先告诉你，但**具体在哪一行、为什么错，要你自己找**）：

- 没有函数封装，全是全局变量
- 没有异常处理（文件不存在直接崩溃）
- 没有 `if __name__ == "__main__"` 保护
- 计算相关系数的公式写错了（或者用了不稳定的数值方法）
- 没有任何注释和文档

## 任务

### 1. Git 仓库初始化

- 建一个 git 仓库，至少进行 **5 次有意义的提交**
- 提交信息必须**符合规范**（推荐 Conventional Commits，例如 `fix: 修正相关系数公式`、`test: 补充边界用例`）

> **注意**：**严禁最后一次性提交**。我们要看的是过程：你怎么一步步发现并修掉问题。
> 建议每次提交对应一个独立的小改动（先加函数封装、再修公式、再加异常、再加测试……）。

### 2. 代码重构

- 将**核心计算封装成函数**
- 添加**完善的异常处理**，至少覆盖：
  - 文件不存在
  - 空文件
  - **列名不匹配**
  - **除零**（某一列取值恒定 → 方差为 0 → 相关系数无定义）
- **修复算法错误**，确保计算结果与 `numpy.corrcoef` 一致
  - 允许引入 numpy 做**验证**
  - 但**核心计算逻辑必须手写**（不允许直接调用 `corrcoef` / `pearsonr` 交差）

### 3. 单元测试

写一个 `test.py`（或 `test_*.py`），用**已知数据**验证你的函数，例如：

- `[1,2,3]` 与 `[2,4,6]` 的相关系数应为 **1.0**
- `[1,2,3]` 与 `[6,4,2]` 的相关系数应为 **-1.0**
- 再补 1~2 个**异常输入**的用例（缺列、空文件、零方差）

### 4. README

写清楚：

- **如何运行**
- **输入文件格式要求**（yaml 有哪些字段、csv 需要什么列、列名规则）
- **输出结果的含义**（n / mean / r 各是什么，r 的取值范围怎么解读）

## 现场验收

现场会给你**一份全新的 yaml + csv**，考官按下列方式运行你的程序：

```bash
python3 <你的入口>.py --config config.yaml
```

要求：

1. **支持 `--config` 指定配置文件路径**（若你也支持位置参数，更好）
2. 结果打印到 **stdout**，且必须包含一行形如：

   ```
   r = <数值>
   ```

   （考官从 stdout 提取该值，与独立实现的结果比对，容差 1e-6）
3. **异常情况下**：打印**可读的错误信息**并以**非 0 退出码**结束
   - ❌ 不允许把 Python 栈回溯（`Traceback ...`）直接抛给用户
4. 输入 csv 的路径写在 yaml 的 `input_csv` 字段中，**相对路径以配置文件所在目录为基准或以当前工作目录为基准均可**，但两种调用方式都要能跑通
