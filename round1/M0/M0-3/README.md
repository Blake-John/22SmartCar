## 场景

上一届学长解脱前留下了一个"能用"的 Python 脚本，说是"处理一下传感器数据就能用"。

但当你真正运行它时，发现**各种报错、各种诡异的结果**。没人给你讲逻辑，你只有代码和一行注释。

## 你拿到的代码

本目录提供：

| 文件 | 说明 |
| :-- | :-- |
| `sensor_analyzer.py` | 存在**多处典型缺陷**的脚本 |
| `sensor_data.csv` | 模拟的传感器数据（列：`time`, `value`） |

**脚本的"原本意图"**：

1. 读取 `sensor_data.csv`（列：`time` 和 `value`）
2. 计算这些数值的**平均值**、**标准差**
3. 剔除其中的**离群值**（Outliers，超过 **2 倍标准差**）
4. 将清洗后的数据保存为 `cleaned_data.csv`
5. 打印一份**统计摘要**

> 缺陷数量：**8 处**。它们并非彼此独立——**修复顺序存在依赖**，
> 前一个不修，后一个的现象会被掩盖。这正是本题的难点。

## 任务

### 1. 修复代码，完成原本的脚本意图

要求修复后：

- 能正确处理给定的 `sensor_data.csv`
- **同时剔除偏大和偏小的离群值**（注意：是"超过 2 倍标准差"的**绝对值**判定）
- 正确输出 `cleaned_data.csv`（内容为清洗后的 `time,value`）
- 正确处理**边界情况**，不允许裸崩（`Traceback`）

### 2. Git 提交

- 同样要求**多次有意义的提交**
- **强烈建议**：每修好一个缺陷就提交一次，提交信息写清"修了什么、现象是什么"
- 这样你的提交历史本身就是一份**调试记录**

### 3. 编写 README —— 问题报告

必须写清：

- **哪里有问题**（定位到具体行/变量）
- **现象是什么**（报什么错 / 结果哪里不对）
- **为什么会有问题**（原理层面的原因）
- **怎么解决的**

建议做成表格，逐条列出你发现的每个缺陷。

## 接口契约（现场按此运行）

现场会给你**一份全新的 `sensor_data.csv`**（列名仍为 `time` / `value`）。
验收按下列方式调用你的程序：

```bash
# 方式一（推荐）：显式指定输入输出
python3 sensor_analyzer.py --input sensor_data.csv --output cleaned_data.csv

# 方式二：无参数，默认读写当前目录下的 sensor_data.csv / cleaned_data.csv
python3 sensor_analyzer.py
```

要求：

1. **至少支持其中一种**调用方式；两种都支持更好
2. 输出到 **stdout** 的摘要中必须包含：

   ```
   均值 mean = <数值>
   标准差 std = <数值>
   ```

   （考官从 stdout 提取并与独立实现比对；`mean` / `std` 是中文还是英文关键字均可，
   但必须包含 `mean`（或"均值"）与 `std`（或"标准差"）字样）
3. **`cleaned_data.csv` 默认写到当前工作目录**
   - ❌ **不要**写死 `/out/...`、`/home/xxx/...` 这类绝对路径
4. 异常输入（文件不存在、空文件、列名不符、非数值内容）**不得抛出栈回溯**
   - 可以报错退出（非 0），也可以给出合理结果——但**不能崩**

## 给你的建议

- **不要一次性重写整个脚本**。先让它跑起来，再逐步逼近正确结果。
  一次性重写你会**说不清自己到底修了什么**，答辩时会很吃亏。
- 先看**报错信息的第一行和最后一行**，定位到具体行号，再去看那一行的**上下文**。
- 修好一个报错后**立刻重跑**——你会发现下一个问题，也可能发现"不报错了但结果不对"。
- **算出来的数字要怀疑**。均值 50、标准差 0，这合理吗？
- **主动构造异常输入**去测你的代码（空文件、缺列、文件不存在）。考官一定会问。
