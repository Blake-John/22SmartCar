# M5-2 ｜ 上位机可视化监控面板：一屏看清全栈健康度

> **难度**：★★
> **综合考察**：ROS2 话题聚合、Web 实时可视化、状态机同步渲染、关键指标仪表盘
> **本题分值权重**：20
> **题目来源**：`创意组一轮考核.md` §M5-2
> **形式**：纯软件（主机侧）。现场带代码，**考官会跑模拟赛并做故障注入**

---

## 0. 这道题在考什么

比赛现场**不能开 10 个终端盯话题**。你需要一屏看清：

> 任务走到哪了？感知/导航/控制在什么状态？有没有故障？裁判在说什么？

本题的架构原则（题面原文，必须遵守）：

> **小车算力留给「感知/规划/控制」，主机算力留给「看、调、记、传」。
> 网络传「状态与指令」，不传「图与云」。**

考四件事：

1. **话题发现**：零硬编码，新话题自动出现（不是一个个写死名字）
2. **数据降频**：小车端只发聚合指标（10Hz），不是把原始数据全推上去
3. **状态同步**：界面的状态机与终端日志**完全一致**
4. **零配置部署**：一条命令起来自动开浏览器，不用手工配面板

> **最容易翻车的地方**：把"聚合"写成"转发"——小车端把十几个原始话题
> 原样推到主机，主机再算。这既费带宽又费小车算力，**违背架构原则**。

## 1. 硬性要求

| # | 要求 | 说明 |
| :-- | :-- | :-- |
| 1 | **小车端只跑一个聚合节点** | 单进程；**< 150 行**、**< 2% CPU**、**< 50MB 内存** |
| 2 | **订阅零硬编码** | 话题模式由**参数**配置（如 `/perception/**`），不是写死名字 |
| 3 | **主机端 Web 应用** | 浏览器单页；技术栈自选（FastAPI+WS / Flask+SocketIO / 纯 asyncio+WS 均可） |
| 4 | **聚合话题** | `/dashboard/metrics`（**10Hz**）、`/dashboard/faults`（事件）、`/dashboard/task_state`（镜像） |
| 5 | **零配置启动** | 一条命令启动并**自动打开浏览器**；所有关键话题自动出现在面板 |
| 6 | **故障流 < 1s** | 故障发生后 **1 秒内**出现在面板上 |
| 7 | **比赛默认不传图像** | 缩略图**默认关闭**，仅调试时开启（1~2Hz 320×240） |
| 8 | **主机资源** | **< 200MB 内存、< 5% CPU** |

> **资源指标怎么量**：用 `psutil` 或 `top`/`ps` 采样，给出**持续 60 秒的平均值**，
> 不是"看一眼任务管理器"。答辩时会要求现场复测。

## 2. 任务分解

### 2.1 小车端：轻量聚合节点

**职责**：**只做聚合与降频**，不做渲染、不做存储。

| 项 | 要求 |
| :-- | :-- |
| 文件 | `dashboard_aggregator.py`（单个 ROS2 Node） |
| 行数 | **< 150 行**（不含注释/空行，要能数得出来） |
| 订阅配置 | 通过 ROS 参数传入话题模式列表，**启动时/运行时**都能改 |
| 计算 | 频率、延迟、丢包率、置信度均值、路径偏离、CPU/温度/电压、网络 RTT |
| 发布 | 见下表 |

**发布的话题**：

| 话题 | 类型 | 频率 | 内容 |
| :-- | :-- | :--: | :-- |
| `/dashboard/metrics` | 自定义 msg 或 JSON String | **10 Hz** | 聚合后的指标字典 |
| `/dashboard/faults` | 事件（String/自定义） | 事件触发 | 故障类型/时间/持续/是否自愈 |
| `/dashboard/task_state` | 状态机镜像 | 变化时 | 当前节点、进度、上下文关键字段 |

**故障检测**：至少实现这三类，且**要在小车端判定**（不是主机端看数判断）：

| 故障 | 判定条件（示例，可自定但要说清） |
| :-- | :-- |
| 传感器降级 | 某话题频率 < 阈值 且 持续 > N 秒 |
| 传感器掉线 | 话题**超时**无数据（> N 秒没收到） |
| 资源告警 | CPU/温度/电压超阈值 |

**必须回答**：

- 为什么**频率/丢包要在小车端算**，而不是把时间戳推上去让主机算？
- `/dashboard/metrics` 为什么定 **10Hz**？（提示：与人眼刷新率、带宽的关系）
- 你的聚合消息**多大**？10Hz 下带宽多少 KB/s？（要算出来）
- 如果监控的原始话题有 20 个，你的聚合节点**开多少订阅**？会不会拖慢感知？

### 2.2 主机端：Web 应用

**布局**（题面指定，不要随意改）：

| 区域 | 内容 |
| :-- | :-- |
| **左** | 任务状态机可视化（节点颜色：灰=待机/绿=运行/蓝=成功/红=失败/橙=降级）；点击节点展开上下文 |
| **中上** | 关键指标实时折线（感知 FPS/置信度/延迟、导航偏离/重规划、控制延迟、电压/温度/CPU） |
| **中下** | 故障标签流（时间/类型/持续/自愈否），可筛选/导出 |
| **右** | 裁判状态（倒计时/阶段/犯规）+ 系统资源仪表盘 |
| **顶** | `/system_ready` 大灯（绿/红）、场景下拉、一键截图/录屏、**紧急停车大按钮** |

**必须回答**：

- 状态机数据怎么到前端？（**订阅 `/dashboard/task_state`**，不是读日志文件）
- 指标折线怎么处理"数据抖动"？（降频？滑动平均？说清你的做法）
- 前端断线重连后，**历史数据**怎么补？（还是只从当前时刻开始？）

### 2.3 通信双轨（架构关键）

| 通道 | 内容 | 频率 | 走什么 |
| :-- | :-- | :--: | :-- |
| **低频** | 状态/指令/参数 | < 10Hz | WebSocket（JSON），可经 `rosbridge` 穿透 NAT |
| **高频** | 聚合指标 | 10Hz | **原生 DDS**（延迟 < 10ms、带宽 < 50KB/s） |
| **图像** | 缩略图 | 默认**不传** | 仅调试开启（`web_video_server` MJPEG 1~2Hz 320×240） |

**必须回答**：

- 为什么**高频指标走 DDS 而不是 WebSocket**？（延迟/开销）
- `rosbridge` 的 JSON 编码开销有多大？10Hz 下可接受吗？
- 图像"默认不传"——**怎么保证学生真的关了**？（提示：做成参数，现场会检查）

### 2.4 零配置部署

| 要求 | 说明 |
| :-- | :-- |
| 一条命令 | `ros2 run <你的包> dashboard` 或 `python dashboard.py` |
| 自动开浏览器 | 启动后自动打开 `localhost:8080`（**不是让学生手输地址**） |
| 话题自动发现 | 启动后不需要手工添加任何话题到面板 |
| 远程同屏 | 手机/平板浏览器能打开（说明你的做法：`rosbridge` / 直接访问主机 IP） |
| 赛后导出 | 一键导出 `dashboard_snapshot_<timestamp>.html`（**含全程数据、可离线回放**） |

**必须回答**：

- "自动发现"具体怎么实现？（ROS2 图查询 `get_topic_names_and_types()`？）
- 如果**启动时某个话题还不存在**（节点后启动），你的面板会怎样？
- 导出的是**静态快照**还是**可交互回放**？数据从哪来（内存缓冲？文件？）

## 3. 现场流程（约 15 分钟）

| 环节 | 内容 | 时间 |
| :-- | :-- | :--: |
| 启动 | 一条命令，看是否自动开浏览器、话题是否自动出现 | 3 min |
| **模拟赛** | 跑 180s：状态机与终端日志是否**完全同步** | 5 min |
| **故障注入** | 拔相机 / 模拟高温 / 低电量 → 看故障流与降级颜色 | 4 min |
| 资源核对 | 现场量小车端与主机端 CPU/内存 | 2 min |
| 追问 | 架构原则（为何不传图）、导出机制、断线重连 | 1 min |

### 故障注入会怎么做

考官会（任选 2~3 项）：

| 注入 | 预期 |
| :-- | :-- |
| 杀掉相机节点 | 故障流 **< 1s** 出现；指标折线断崖；状态机节点变橙 |
| 模拟高温（发一个假温度话题） | 资源仪表盘告警 |
| 拔网线/断 DDS | 面板显示"失联"而不是**卡住不动**（要能区分"没数据"与"数据是 0"） |

> **最后一条是常见盲区**：很多实现把"没收到数据"画成 0，
> 看起来像"指标突然掉到 0"而不是"失联"，现场会被指出来。

## 4. 交付物与格式

```
M5-2/
├── robot_side/
│   └── dashboard_aggregator.py    # ★ 小车端聚合节点（< 150 行）
├── host_side/
│   ├── app.py                     # Web 应用入口
│   ├── templates/                 # 或前端静态文件
│   ├── static/
│   └── requirements.txt
├── config/
│   └── dashboard.yaml             # 话题模式配置（零硬编码的关键）
├── tools/
│   └── measure_resources.py       # 量 CPU/内存（可复现）
├── docs/
│   ├── architecture.md            # 双轨通信 + 为何不传图
│   ├── layout.png                 # 界面截图（标注五个区域）
│   └── fault_rules.md             # 故障判定规则（阈值与持续时间）
└── README.md
```

### 运行约定

```bash
# 小车端（单进程）
ros2 run <pkg> dashboard_aggregator --ros-args \
    -p topic_patterns:="[/perception/**,/navigation/**,/control/**,/hw/**]"

# 主机端（一条命令 + 自动开浏览器）
python host_side/app.py --port 8080
```

### `dashboard.yaml` 示例（零硬编码）

```yaml
topic_patterns:
  - "/perception/**"
  - "/navigation/**"
  - "/control/**"
  - "/hw/**"
  - "/referee/**"
special_topics:
  task_state: "/task_state"
  system_ready: "/system_ready"
publish:
  metrics_hz: 10
  faults_topic: "/dashboard/faults"
fault_rules:
  freq_low:
    threshold_hz: 10.0
    duration_s: 2.0
  topic_timeout_s: 3.0
  cpu_high_pct: 85.0
  temp_high_c: 85.0
  voltage_low_v: 10.5
video:
  enable: false          # 比赛默认关闭（现场会检查）
  hz: 1
  width: 320
  height: 240
```

## 5. 明确禁止

- 禁止把"聚合"写成"转发"（小车端推原始数据让主机算，违背架构原则）
- 禁止话题名硬编码（现场会改配置看是否生效）
- 禁止比赛模式下传图像（现场会检查 `video.enable`）
- 禁止故障判定放在主机端靠"看数猜"（要在小车端用**规则**判）
- 禁止"没数据"画成 0（要能区分失联与真值 0）
- 禁止导出只是截图（要求含数据、可离线回放）
- 禁止要求手工添加话题/手工配面板（零配置是硬性要求）
