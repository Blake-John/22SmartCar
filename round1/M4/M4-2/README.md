# M4-2 ｜ 传感器：编码器测速与 IMU 姿态解算

> **难度**：★★
> **综合考察**：编码器测速、I2C 传感器读取、互补滤波/卡尔曼、数据可视化
> **本题分值权重**：20
> **题目来源**：`创意组一轮考核.md` §M4-2
> **形式**：自备开发板 + 编码器电机 + MPU6050；现场带代码与数据，**考官会发一段未见过的 IMU 原始数据**让你离线解算

---

## 0. 这道题在考什么

从"能读寄存器"到"能拿出可信的物理量"。三个能力：

1. **测速**：把脉冲变成转速，且知道**在低速时为什么不准**
2. **读传感器**：I2C 通信正确、原始值单位与量程对得上
3. **融合**：用互补滤波/卡尔曼把陀螺仪与加速度计**互补**成可用的俯仰角
4. **归因**：能解释曲线上的毛刺是**从哪来的**

> 现场考点是第 4 条：考官给你一段**没见过的 IMU 原始数据流**，
> 你要**离线**解算出角度曲线，与独立参考真值误差 **≤5°**。
> 这检验你的算法是否真的可复现，而不是"在我的硬件上凑出来的参数"。

## 2. 任务分解

### 2.1 编码器测速

**两种方案任选**：

| 方案 | 做法 | 特点 |
| :-- | :-- | :-- |
| **定时器编码器模式**（推荐） | 定时器硬件正交解码，读 CNT 差值 | 不占 CPU，高速不丢脉冲 |
| 外部中断计数 | 脉冲边沿触发中断，1s 计一次数 | 简单，但**高速时中断开销大**，可能丢脉冲 |

**计算公式**（文档里要写清）：

```
转速(r/min) = 脉冲数 / (每圈脉冲数 × 减速比) × 60 / 采样窗口(s)
```

**必须回答**：

- 你的**每圈脉冲数**是多少？怎么来的？（编码器线数 × 4 倍频？× 减速比？）
- **1s 窗口**在低速时有什么问题？（提示：低速时窗口内脉冲很少，量化误差大）
- 如果要求**低速也准**，你会怎么改？（提示：测周期法 vs 测频率法）

**要求**：同时输出**原始计数值**与**换算后的转速**（便于核对）。

### 2.2 读取 MPU6050

| 项 | 要求 |
| :-- | :-- |
| 接口 | I2C（说明地址：0x68 或 0x69，取决于 AD0 引脚） |
| 初始化 | 唤醒（解除 sleep）、设置量程（±2g / ±250°/s 或更高） |
| 输出 | 加速度三轴 (ax, ay, az) 与角速度三轴 (gx, gy, gz) |
| **单位** | 原始 LSB **必须换算成物理单位**（g 和 °/s），并写出换算系数 |

**换算示例**（±2g / ±250°/s，16 位输出）：

```
加速度: 16384 LSB/g      -> ax_g = raw / 16384.0
角速度: 131   LSB/(°/s)  -> gx_dps = raw / 131.0
```

**必须回答**：

- 你的量程设的是多少？为什么？（比赛场景下量程选小了会削顶、选大了分辨率下降）
- 读数据时 I2C 速率多少？（400kHz 相比 100kHz 对采样率的影响）
- 有没有校验 WHO_AM_I 寄存器？（不校验的话，接线错会读到全 0 或乱码）

### 2.3 融合俯仰角

**先确定坐标系约定**（不写清楚的话，俯仰与横滚会搞反）：

| 轴 | 指向 |
| :-- | :-- |
| X | 车头前方 |
| Y | 车身右侧 |
| Z | 垂直向上（**水平静止时 `az ≈ +1g`**） |

**绕 Y 轴转 = 俯仰（pitch）**，由加速度计估算：

```
pitch_acc = atan2(-ax, az) × 180/π
```

> **注意符号与轴**：`atan2(ay, az)` 算的是**绕 X 轴的横滚（roll）**，
> 不是俯仰。两者在水平时都是 0，容易混——**先想清楚你的车绕哪根轴点头**。
> （若你的 IMU 贴装方向与上表不同，要说明你怎么换算到车身系。）

**互补滤波**（推荐入门）：

```
pitch = α × (pitch + gyro_y × dt) + (1 - α) × pitch_acc
```

> 陀螺仪也用**对应那根轴**：估算俯仰用 `gyro_y`，估算横滚用 `gyro_x`。
> 用错轴的典型症状：车头点头时角度几乎不动，但侧倾时角度乱跳。

**或一阶卡尔曼**（可选，但要说清 Q/R 怎么定）。

**必须回答**：

- **α 怎么定的**？和时间常数 τ 的关系是什么？（`α = τ/(τ+dt)`）
- 为什么**陀螺仪**积分会漂、**加速度计**噪声大，而两者融合能互补？
- 加速度计在**什么情况下会失准**？（提示：车在加速/刹车时，`atan2` 把线加速度当重力）

**自检方法**（必做，现场会问）：

- 把车**车头向上抬** 30°，看你的 pitch 是否**朝正确方向**变化约 30°
- 把车**向右侧倾** 30°，看 pitch 是否**基本不动**（动了说明你算的是 roll）
- 如果你要输出 roll，就明确说"本题以 pitch 为准，roll 另算

### 2.4 漂移实测（60 秒静置）

| 项 | 要求 |
| :-- | :-- |
| 条件 | 传感器**静止不动**放在桌上 60 秒 |
| 记录 | 每秒记一个角度值，存 CSV |
| 指标 | **总漂移**（末值 − 初值）或**漂移率**（度/分钟） |
| 对比 | **纯陀螺仪积分** vs **融合后**，两条曲线都画出来 |

> 这个对比是本题的重点：两条曲线会呈现明显不同的形态，
> 你要**自己解释差异从哪来**、以及融合到底改善了哪个指标。

**必须回答**：

- 你的零偏（bias）是多少？**怎么得到这个数的**？
- **不做零偏补偿**会怎样？给出前后对比数字。
- 融合后的漂移主要来自哪里？

### 2.5 毛刺归因

用**串口示波器**（VOFA+ / SerialPlot / 或其他）录一段"**手动转动一圈**"的实时曲线。

**贴图 + 解释**：

| 现象 | 你要解释 |
| :-- | :-- |
| 曲线上的**尖刺** | 从哪来？（I2C 读失败？量程削顶？机械振动？） |
| 转动停止后的**回弹** | 为什么？（融合权重？加速度计的瞬态？） |
| **周期性的小波动** | 与什么同频？（电机振动？采样率与转速的拍频？） |

**要求**：每条归因都要有**验证手段**（比如"我降低采样率后尖刺消失，说明是 I2C 阻塞"）。

| :-- | :-- | :--: |

### 离线复算的形式

考官提供 `imu_raw.csv`（列：`t, ax, ay, az, gx, gy, gz`，单位为 g 与 °/s），
你用它跑自己的融合算法，输出角度曲线，与独立参考真值比对：

- **误差 ≤5°** 为通过
- 需要**说明你的预处理**（零偏补偿用的是哪一段数据）

> 注意：这段数据的**传感器型号与量程与你自己的可能不同**，
> 所以你的算法**不能依赖写死的零偏值**，要能从数据本身估计。

## 5. 明确禁止

- 禁止只输出原始 LSB 值不给物理单位（无法判断量程是否正确）
- 禁止**写死零偏**（现场数据与你自己的传感器不同，会直接失败）
- 禁止不校验 `WHO_AM_I`（接线错误时无法区分"硬件坏"与"代码错"）
- 禁止用阻塞式 I2C 读把主循环卡住（采样率会掉，曲线会失真）
- 禁止只用纯陀螺仪积分当"融合结果"（漂移会被现场看出来）
- 禁止毛刺归因只有结论没有验证手段
- 禁止离线脚本依赖特定硬件的绝对时间（要基于数据自身的时间列）
