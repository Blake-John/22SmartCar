# M6 展示指南

> 在本机上运行。
> 演示前先做三件事：摄像头能出图、自己准备好考核展示的视频或数据集、电脑装好驱动版本。

---

## M6-1 模型到板端

1. 现场重跑一次 `export_onnx.py`，再跑一致性脚本，给出 **CosSim** 与最大绝对差。
2. 用 `--device cpu` / `gpu`（有则测）各跑 15~20 秒，切给考官看。
3. 开摄像头跑 30 秒，画面要有框、类别、置信度、FPS。
4. 打开 `benchmark.yaml`，念六项指标（含冷启动与稳态分开的那两行）（仅在自己电脑上跑，重点对比 cpu / gpu）。

---

## M6-2 量化与硬件加速

1. 现场跑一次静态量化脚本，确认能复现。
2. 给出 FP32 与量化后的 mAP、逐类结果、FPS 倍数。
3. 打开 `quant_analysis.csv` 与热力图，指出**损失最大的层**并解释原因。
4. 报达标情况：mAP 下降 <2%、FPS ≥2× FP32。

---

## M6-3 会话调优与 CUDA Graph

1. 用默认配置跑一遍基线，确认约 22 FPS / P95 ~50 ms（和报告对得上）。
2. 现场切 EP：`cpu → cuda → tensorrt`，各跑 15 秒，看 `ep_comparison.yaml` 是否一致。
3. 打开 `session_tuning.csv`，指出**哪个参数贡献最大**、依据是哪几行。
4. 跑 1000 帧，念 P95 / P99 / max，和报告里的数对照。
5. 打开 `cuda_graph.md`，说清开与关差多少、什么时候捕获会失败。

---

## M6-4 多线程推理管线

1. 现场跑三方案（`--threads 1/2/3`），算加速比，看检测框稳定输出帧率、卡顿情况，展示多线程提升效果。
2. 查代码：队列在哪、双缓冲怎么换、锁加在哪，**指出哪一行可能发生拷贝**。
3. 跑 90 秒并看 RSS 曲线（跑完再去考核，提前将数据和图像保存下来）。
4. `pytest -q`，确认单测用的是 Mock 引擎、不依赖真实模型。
