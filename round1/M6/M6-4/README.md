# M6-4 ｜ 多线程推理管线：重叠预处理·推理·后处理

> **难度**：★★★★
> **综合考察**：多线程/异步编程、生产者-消费者、零拷贝内存、共享资源管理
> **本题分值权重**：40
> **题目来源**：`创意组一轮考核.md` §M6-4
> **形式**：自备开发板 + 摄像头；现场带代码与数据实测

---

## 0. 这道题在考什么

板子上只跑**一个模型**，但传感器 30Hz 不断喂帧。三级耗时：

```
预处理 20ms + 推理 33ms + 后处理 10ms = 63ms/帧  ->  15.9 FPS
```

串行的话永远达不到 30 FPS。你要做的是**流水线并行**：
"前一帧推理时，后一帧在预处理"。

**理论上限**（受最慢一级限制）：

```
max(20, 33, 10) = 33ms/帧  ->  30.3 FPS
加速比 1.91×
```

考四件事：

1. **架构**：三级流水线 + 有界队列 + **背压**（不丢帧、不爆内存）
2. **零拷贝**：帧数据在队列里**不许反复拷贝**（这是性能杀手）
3. **线程安全**：无死锁、无竞态；引擎句柄要**线程安全**
4. **可验证**：三方案（串行/双线程/三线程）对比，**加速比 ≥1.6×**

> **最容易翻车的地方**：队列里放**拷贝过的帧**。
> 每帧 640×480×3 ≈ 900KB，30FPS 下每秒拷贝 27MB——
> 拷贝开销会把流水线省下的时间吃回去。所以题面明确要求**零拷贝/双缓冲**。

## 1. 硬性要求

| # | 要求 | 说明 |
| :-- | :-- | :-- |
| 1 | **三级流水线** | Preprocess / Inference / Postprocess 各一个独立线程 |
| 2 | **有界队列** | 如 `queue.Queue(maxsize=4)`；**队列满时等待**（背压） |
| 3 | **零拷贝/双缓冲** | 帧数据**不许**在队列中序列化-反序列化或反复拷贝 |
| 4 | **线程安全** | 推理引擎句柄单例 + 锁/无锁；无死锁、无竞态 |
| 5 | **三方案对比** | 串行 / 双线程 / 三线程，各记录五项指标 |
| 6 | **加速比 ≥1.6×** | 三线程 vs 串行 |
| 7 | **3 分钟稳定** | 无崩溃、**无内存泄漏**（RSS 波动 < 50MB） |
| 8 | **单元测试** | 覆盖线程安全 / 背压 / 异常恢复，`pytest` 全绿 |

> **第 5 条的判定口径**：三方案必须在**同一模型、同一板子、同一输入源**下测，
> 否则加速比没有意义。

## 2. 任务分解

### 2.1 三级流水线架构

```
[帧源 30Hz]
    │
    ▼
┌──────────────┐   queue_pre    ┌──────────────┐   queue_post   ┌───────────────┐
│ Preprocess   │ ─────────────> │ Inference    │ ─────────────> │ Postprocess   │
│ 缩放/归一化   │   maxsize=4    │ 模型推理      │   maxsize=4    │ NMS/解码/绘制  │
│ 通道变换      │                │              │                │ 发布结果       │
└──────────────┘                └──────────────┘                └───────────────┘
```

**要求**：

| 项 | 说明 |
| :-- | :-- |
| 线程数 | 三级各一个；**不要**给每帧新建线程 |
| 队列 | 有界；满时 Preprocess **阻塞等待**（背压），不是丢帧也不是无限增长 |
| 退出 | 收到停止信号时，三线程都要能**优雅退出**（不是 daemon 强杀） |
| 异常 | 某一级抛异常时，其余线程要能感知并退出（不要一个挂了其他还跑） |

**必须回答**：

- **背压**为什么用"阻塞"而不是"丢帧"？（提示：比赛场景下丢帧的后果）
- `maxsize` 设 1 / 4 / 16 分别会怎样？（吞吐 vs 延迟的权衡）
- 消费者比生产者慢时，队列会怎样？你怎么观察到的？

### 2.2 零拷贝与双缓冲

**问题**：`queue.put(frame)` 放的是**引用**还是**拷贝**？
在 Python 里看起来是引用，但如果上游复用同一个 buffer，就会出现**数据竞争**。

**要求**（择一实现，并说明）：

| 方案 | 做法 |
| :-- | :-- |
| **双缓冲** | 维护 2 个 buffer，Preprocess 写 A 时 Inference 读 B，处理后交换 |
| **缓冲池** | 预分配 N 个 buffer，用后归还；用 `queue` 传递**索引**而非数组 |
| **共享内存** | `multiprocessing.shared_memory` + 元数据（适合多进程） |
| **零拷贝视图** | `torch.from_numpy(arr)` 共享底层 buffer（同进程多线程适用） |

**必须验证**：

| 验证项 | 怎么验 |
| :-- | :-- |
| **没有多余拷贝** | 统计单帧的内存分配次数，或对比有/无拷贝的耗时 |
| **数据正确** | 产出的检测框与串行版本**一致**（不能因竞争导致错帧） |
| **内存占用** | 4 路输入并发时总内存 < 300MB（串行约 800MB） |

**必须回答**：

- 你怎么证明"没在拷贝"？（给出证据，不是"我用了引用"）
- 双缓冲下，如果 Inference **比 Preprocess 慢很多**，会怎样？
- 如果误用了同一 buffer，会出现什么现象？（提示：偶发的"花屏"或错框）

### 2.3 线程安全与资源竞争

| 项 | 要求 |
| :-- | :-- |
| 引擎句柄 | 单例；说明是否线程安全（ORT Session 通常可并发，TensorRT Context **不可**） |
| CUDA 流 | 若用多流：说明哪个阶段用哪个流；是否需要同步 |
| 共享状态 | 统计计数用锁或 `atomic`（Python 里注意 GIL 不是万能的） |
| 同步原语 | `threading.Event` / `Queue` / `Condition` 各用在哪，说清 |
| 死锁防护 | 队列满 + 队列空同时发生时会怎样？有没有超时兜底？ |

**必须回答**：

- Python 有 GIL，为什么这个流水线**仍然能加速**？（提示：推理与 I/O 会释放 GIL）
- TensorRT 的 `ExecutionContext` **不能多线程共享**——你怎么处理的？
- 如果推理引擎**偶尔失败**（返回 None），你的管线怎么处理？（重试？跳过？）

### 2.4 性能验证

**三方案对比**：

| 方案 | 说明 |
| :-- | :-- |
| **① 串行** | Preprocess → Infer → Postprocess 全做完再取下一帧 |
| **② 双线程** | Preprocess 与 Infer 并行（后处理仍在推理线程里） |
| **③ 三线程** | 三级全并行 |

**每个方案记录**：

| 指标 | 说明 |
| :-- | :-- |
| FPS | 端到端吞吐 |
| P95 延迟 | 从"帧进入管线"到"结果发布" |
| 内存占用 | RSS |
| CPU 各核利用率 | 看是否真的并行（不是单核跑满） |
| GPU 利用率 | 同上 |

**输出** `pipeline_benchmark.yaml`：三方案 + **加速比** + **瓶颈分析**。

**必须回答**：

- 为什么**双线程**的加速比通常低于 2×？（提示：最慢一级 + 后处理仍串行）
- 三线程的**瓶颈**在哪一级？你怎么从数据看出来的？
- 如果推理只要 5ms（很快），流水线还有意义吗？（提示：瓶颈转移到别处）

### 2.5 稳定性与单元测试

**3 分钟稳定运行**：

| 验证 | 阈值 |
| :-- | :-- |
| 不崩溃 | 3 分钟无异常退出 |
| 无内存泄漏 | **RSS 波动 < 50MB**（给出采样曲线） |
| 无死锁 | 全程无卡住 |

**单元测试**（`pytest tests/`）：

| 测试 | 覆盖什么 |
| :-- | :-- |
| 背压 | 队列满时生产者等待（不是丢帧或崩溃） |
| 线程安全 | 并发写入统计计数不丢 |
| 异常恢复 | 推理线程抛异常 → 其他线程优雅退出 |
| 优雅退出 | 发停止信号后，三线程都能 join 上 |
| 数据正确 | 流水线输出与串行输出一致 |

**必须回答**：

- 内存泄漏你是怎么定位的？（如果 RSS 一直涨，先怀疑什么？）
- 单元测试里怎么 **Mock 推理引擎** 才能不依赖真实模型？
- 怎么测"没有死锁"？（超时断言？）

## 5. 明确禁止

- 禁止在队列里放**拷贝过的帧**（必须零拷贝/双缓冲，且要给证据）
- 禁止队列无界（内存会涨到爆）
- 禁止用"丢帧"解决背压（题面明确要求不丢帧）
- 禁止每帧新建线程（开销比收益大）
- 禁止只报三线程的 FPS 不给对比（加速比必须在同一条件下测）
- 禁止用 daemon 线程强退代替**优雅退出**
- 禁止单测依赖真实模型/摄像头（要用 Mock）
- 禁止只报 FPS 不报 **P95 延迟**（吞吐高但延迟大是没用的）
- 禁止不做内存泄漏验证（3 分钟 RSS 曲线是硬性要求）
