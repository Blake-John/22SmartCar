# M6-2 ｜ 量化与硬件加速：INT8 / INT4 部署 + 性能对比

> **难度**：★★
> **综合考察**：量化原理、PTQ/QAT、硬件加速器部署、精度-性能权衡
> **本题分值权重**：20
> **题目来源**：`创意组一轮考核.md` §M6-2
> **形式**：自备开发板；现场带量化模型与报告实测

---

## 0. 这道题在考什么

M6-1 的 FP32 模型在板子上只能跑 **15 FPS**，比赛要求感知节点 **≥ 30 FPS**。
你需要**量化**（INT8，进阶到 INT4）把速度翻倍，但**精度损失要 < 2%**。

考四件事：

1. **量化管线**：PTQ（后量化）**至少两种方案**跑通，说清差异
2. **精度归因**：**逐层**分析精度损失，定位**损失最大的层**并解释原因
3. **多后端对比**：通用 ORT 与平台专属加速器（TensorRT / RKNN）都试
4. **不达标时能补救**：mAP 掉超 2% 要做 **QAT 微调**或**混合精度**

> **最容易翻车的地方**：只报"INT8 后 mAP 0.83，OK"。
> 题目要的是**为什么掉、掉在哪一层**——所以必须有逐层分析与可视化。

## 2. 任务分解

### 2.1 量化管线

**PTQ（后量化）**——至少两种：

| 方案 | 做法 | 特点 |
| :-- | :-- | :-- |
| **动态量化** | `torch.quantization.quantize_dynamic` | 只量化权重，激活运行时量化；简单，加速有限 |
| **静态量化（QDQ）** | ONNX Runtime `quantize_static` / `opt_qdq` | 需要校准集；加速明显，是主流做法 |
| **平台量化** | TensorRT `--int8 --calib=` / RKNN `hb_mapper` | 与硬件结合最紧，效果通常最好 |

**校准集要求**：

| 项 | 要求 |
| :-- | :-- |
| 数量 | 100~500 张 |
| 来源 | **真实赛道图像**（不是合成、不是训练集） |
| 分布 | 覆盖不同光照/场景（否则量化参数偏） |
| 记录 | 说明怎么采的、多少张、覆盖什么 |

**必须回答**：

- **动态量化 vs 静态量化**的本质区别是什么？为什么静态量化通常更快？
- 校准集**只用 10 张**会怎样？用 1000 张呢？（边际收益）
- 校准集的**分布**为什么重要？（用你自己的实验说明）

### 2.2 精度回退分析（本题重点）

**逐层/逐算子对比**量化前后：

| 指标 | 说明 |
| :-- | :-- |
| CosSim | 该层输出与 FP32 输出的余弦相似度 |
| KL 散度 | 输出分布的差异 |
| 相对误差 | 或 max abs diff |

**输出**：

- `quant_analysis.csv`：每层一行（层名 / CosSim / KL / 是否量化）
- **可视化热力图**：哪几层损失大，一眼看出

**必须定位并解释**：

| 问题 | 要写清 |
| :-- | :-- |
| **损失最大的层**是哪层？ | 具体名字 |
| 为什么是它？ | 三种典型原因：① 算子不支持量化 ② 校准数据不足 ③ 数值范围异常（如某层激活值跨度极大） |
| 你的证据是什么？ | 不能只猜，要有数据支撑 |

**必须回答**：

- 为什么**第一层和最后一层**往往较敏感？（输入是像素、输出要精确）
- 如果某层激活值**范围异常**（比如有极端离群值），量化会怎样？
- **NMS** 这种后处理算子要不要量化？为什么？

### 2.3 硬件加速器部署

按你的板子选**至少一种**：

| 平台 | 工具链 | 产物 |
| :-- | :-- | :-- |
| **Jetson** | `trtexec --int8 --calib=calib/` 或 `polygraphy` | `best.engine` |
| **地平线 RDK** | `hb_mapper` / `hbdk` | `best.bpu` |
| **RK3588** | RKNN-Toolkit2 | `best.rknn` |
| **通用** | NCNN / MNN | `best.bin` / `.param` |

**每种后端要输出**：

- 模型文件
- `deploy_config_<backend>.yaml`（输入输出规格、量化参数、依赖版本）

**必须回答**：

- 平台加速器相比通用 ORT，**快在哪**？（算子融合？专用硬件？）
- 转换过程中如果**某个算子不支持**，工具会怎么报？你怎么处理？
- 转换后的模型**精度**与 ONNX INT8 相比如何？

### 2.4 性能对比表

**必须逐类报告精度**（不能只给总 mAP）：

| 模型/后端 | mAP（总） | mAP（逐类） | FPS | P95 延迟 | 内存 | 文件大小 |
| :-- | :--: | :-- | :--: | :--: | :--: | :--: |
| FP32 ONNX (CPU) | 0.850 | … | ? | ? | ? | 28MB |
| INT8 动态 (CPU) | ? | … | ? | ? | ? | ? |
| INT8 静态 (CPU) | ? | … | ? | ? | ? | ? |
| INT8 平台加速器 | ? | … | ? | ? | ? | ? |

**达标判定**：

- **mAP 下降 < 2%**（相对 FP32）
- **FPS ≥ 2× FP32**

**必须回答**：

- 你的**最差类别**是哪个？量化后掉了多少？
- 如果某类**样本很少**，量化后更容易掉吗？为什么？
- 你推荐哪个方案上比赛？**代价**是什么？

### 2.5 不达标时的补救

**若 mAP 掉 > 2%**，必须做其一：

| 方案 | 做法 | 记录 |
| :-- | :-- | :-- |
| **QAT** | 量化感知训练微调 **1~2 epoch** | 微调数据/超参/前后 mAP |
| **混合精度** | 量化主体 + 保留敏感层/不支持算子为 FP32 | 哪些层保留、为什么、收益多少 |

**必须回答**：

- QAT 微调后 mAP 恢复了吗？**代价**是什么（训练时间、需要标注数据）？
- 混合精度里你保留了哪几层？**依据**是什么（来自 §2.2 的逐层分析）？

### 2.6 INT4 进阶（可选，但鼓励）

> **为什么是"可选"**：INT4 的硬件支持与精度风险都比 INT8 大——
> Jetson Orin 的 TensorRT 支持 INT4 但需显式构造；
> RDK X3 的 BPU 以 INT8 为主，INT4 支持有限。
> 所以本题**以 INT8 为达标线，INT4 作为进阶**。

**关键事实**（答题时要说清）：

| 项 | 说明 |
| :-- | :-- |
| 量化对象 | INT4 通常只量化**权重**，**激活值仍为 INT8 或 FP16**（即 W4A16 / W4A8） |
| 体积收益 | 权重约为 FP32 的 **1/8**（INT8 是 1/4） |
| 精度风险 | 常掉 **3~8%**，需 QAT 或 AWQ/GPTQ 类方法；INT8 通常只掉 1~2% |
| 硬件前提 | 不是所有加速器都支持；**先确认你的板子** |

**若你的板子支持**，请给出：

| 项 | 要求 |
| :-- | :-- |
| 方案 | 用的什么方法（QAT？AWQ？工具链自带？） |
| 精度 | 与 FP32 / INT8 对比（**逐类**） |
| 速度 | FPS 与 P95 延迟（是否真的比 INT8 更快？**不一定**） |
| 代价 | 精度、工程量、稳定性方面的代价 |

**若你的板子不支持**，请给出：

- 你**怎么确认**不支持的（工具链报错？文档？实测？）
- 查到的**硬件/工具链限制**是什么
- 如果未来要上 INT4，你会怎么做

**必须回答**：

- INT4 的**收益主要来自哪**（体积？带宽？算力）？为什么实际加速常不如 INT8 明显？
- 为什么 INT4 通常**不量化激活值**？
- 对 YOLO 这类检测模型，INT4 最容易在**哪一层**出问题？

| 环节 | 内容 | 时间 |

```
M6-2/
├── quantize/

│   ├── ptq_static.py         # 静态量化（含校准）
│   ├── to_platform.py        # 平台加速器转换（TensorRT/RKNN/...）
│   └── qat_finetune.py       # QAT 微调（若不达标才需要）
├── calib_dataset/            # ★ 校准集（100~500 张真实图）
│   └── README.md             # 采集说明（来源/数量/分布）

│   ├── best_fp32.onnx
│   ├── best_int8_dynamic.onnx
│   ├── best_int8_static.onnx
│   └── best.engine / .rknn / .bin
├── tools/
│   ├── layer_analysis.py     # ★ 逐层 CosSim/KL 分析
│   ├── eval_map.py           # 逐类 mAP 评估
│   └── benchmark_multi.py    # 多后端性能对比
├── results/
│   ├── quant_analysis.csv    # 逐层数据
│   ├── heatmap.png           # ★ 可视化热力图
│   ├── benchmark_multi_backend.yaml
│   └── per_class_map.csv     # ★ 逐类精度

```

### 运行约定

```bash
# 静态量化（需要校准集）
python quantize/ptq_static.py --onnx models/best_fp32.onnx \
    --calib calib_dataset/ --out models/best_int8_static.onnx

# 逐层分析
python tools/layer_analysis.py --fp32 models/best_fp32.onnx \
    --int8 models/best_int8_static.onnx --out results/quant_analysis.csv

# 逐类评估（现场用考官的测试集）
python tools/eval_map.py --model models/best_int8_static.onnx \
    --data /path/to/test_100/ --per-class --out results/per_class_map.csv

# 多后端对比
python tools/benchmark_multi.py --models a.onnx,b.engine --seconds 60 \
    --out results/benchmark_multi_backend.yaml
```

## 5. 明确禁止

- 禁止用训练集做校准（精度会虚高，现场会问采集来源）
- 禁止只报总 mAP（题面要求**逐类**）
- 禁止只报"掉了多少"不报**掉在哪一层**（逐层分析是重点）
- 禁止只跑一种量化方案（要求至少两种）
- 禁止精度不达标却不做补救（QAT 或混合精度）
- 禁止性能数据只测几帧（沿用 M6-1 的 60 秒要求）
- 禁止把"转换成功"当成"部署成功"（要实测精度与速度）
