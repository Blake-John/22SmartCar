# M2-1 ｜ 传统视觉管线：数据先行的红绿灯检测

> **难度**：★
> **综合考察**：OpenCV 核心操作、色彩空间、阈值/形态学、轮廓检测、相机标定、数据评估
> **本题分值**：10 分
> **题目来源**：`创意组一轮考核.md` §M2-1
> **形式**：自备手机/相机拍视频，自标注、自评估；现场只带数据与代码，**不摆任何实物**

---

## 0. 这道题在考什么

比赛里最基础的能力：**给你一个能跑的视觉方案，你能说清它的边界在哪里**。
"在光照好的实验室能检测到"不算本事——**知道它什么时候会失效、为什么失效**才算。

所以本题的重心在**数据**上：你有没有一段自己拍的、标好的、分得清"调参用的"和"没见过的"数据；
你能不能拿这张表说清自己在哪掉分。代码写得多漂亮是次要的。

## 1. 硬性要求

| # | 要求 | 说明 |
| :-- | :-- | :-- |
| 1 | **只用传统视觉方法** | OpenCV / NumPy。**禁止**深度学习、禁止调用现成的"红绿灯检测"库 |
| 2 | **数据自己拍** | 手机 / 相机 / 网络摄像头均可，**≥3 段、每段 ≥30 s、≥30 fps** |
| 3 | **光照覆盖** | 白天顺光、夜间或暗光、逆光/强光，**各 ≥1 段** |
| 4 | **自己标注** | 每段 ≥100 帧，标 状态 / 灯中心像素坐标 / 半径（或面积），格式见 §4.3 |
| 5 | **留出测试段** | 至少 **1 段完全不参与调参**，只用于最后评估；报告里要分开写 |
| 6 | **输出四项** | 亮灯状态（红/黄/绿/无）、中心坐标、面积（或半径）、**最小外接圆** |
| 7 | **量化评估** | `eval.py` 出指标表：状态准确率、中心误差 P50/P95、漏检率、误检率，按段/光照拆开 |
| 8 | **文档 ≥5 种失效** | 每条要有**现象 + 复现方法 + 原理层原因 + 在你数据里出现几次** |
| 9 | **内参自标定** | 棋盘格可打印、也可用显示器全屏显示，**写清用了哪种**；结果存 `camera_calibration.yaml`（M2-2 会读） |

> 不需要灯箱、不需要实体红绿灯、不需要现场摆场景。
> 拍真实路口可以；在暗室里用手机屏幕显示红/黄/绿三色块、自己拍下来也可以（但必须是实拍，不能拿网图当数据）。

## 2. 任务分解

### 2.1 数据采集与标注

| 项 | 要求 |
| :-- | :-- |
| 拍什么 | 画面里**固定一盏灯**（一条车道的信号灯）。多盏灯入画时裁掉，或只标你判定的那一盏 |
| 怎么拍 | 手持或架住都行。**别开数码变焦**——内参是按广角标的，变焦后全错 |
| 抽帧 | 每段按 10 Hz 抽（30 fps 视频每 3 帧取 1 张），每段 ≥100 帧 |
| 标注 | 状态 `red` / `yellow` / `green` / `none`；`none` 表示画面里没灯（遮挡、出画、灭灯） |
| 均衡 | 红灯段通常最长、黄灯只有 3 s。黄灯帧不够就多拍几个周期，别用别的段凑数 |
| 留出 | 先定好哪一段是测试段，**调阈值时不要看它的指标** |

> 标注质量比数量重要：中心点标在灯的几何中心，半径标到灯的亮面边缘。
> 自己抽 20 帧复核一遍，错超过 2 帧就重标。

### 2.2 相机标定

| 步骤 | 要求 |
| :-- | :-- |
| ① 标定板 | 棋盘格 9×6 内角点。**打印或用显示器全屏显示都可以**（屏幕显示时把亮度调高、关掉自动亮度） |
| ② 边长 | 必须量出方格边长（mm）写进 yaml。打印的用尺量，屏幕显示的用"屏幕像素间距 × 显示缩放"算，写清算法 |
| ③ 采集 | 15~20 张，不同角度、不同距离，覆盖画面四角与中心 |
| ④ 标定 | `cv2.calibrateCamera`，报重投影误差 RMSE；> 0.5 px 要解释，> 1.5 px 视为失败 |
| ⑤ 保存 | `camera_calibration.yaml`，格式见 §4.2 |

**自检**：换一张未参与标定的棋盘图重投影，误差还小吗？fx 与 fy 接近吗？k1 的符号和量级合理吗？

### 2.3 检测管线

**处理流程（顺序不可颠倒，每一步都要在文档里说明为什么）**：

```
读帧 → 去噪 → 颜色分割 → 形态学清理 → 轮廓查找 → 形状/面积过滤
     → 状态判定 → 最小外接圆 → 标注输出
```

| 环节 | 必须说清的问题 |
| :-- | :-- |
| 颜色分割 | 用 HSV 还是 RGB？**为什么**？阈值是多少、怎么定的？ |
| 形态学 | 用了开/闭/腐蚀的哪几种？核多大？解决什么问题？ |
| 过滤 | 面积上下限怎么定？只靠颜色够吗——**同色干扰物**怎么排除？ |
| 状态判定 | 如果两个掩码同时命中怎么办？如果**全都没命中**怎么办（必须输出"未识别"，不许崩） |

代码必须能读**单图 / 视频 / 摄像头**三种输入，不允许现场改代码才能跑。

### 2.4 量化评估

写一个 `eval.py`，读标注与预测，输出 `results/eval.csv` 和一张摘要表：

| 指标 | 定义 |
| :-- | :-- |
| 状态准确率 | 只统计 `gt != none` 的帧；同时给混淆矩阵 |
| 中心误差 | 像素误差的 P50 / P95，并给出归一化值 `err / r` |
| 漏检率 | 标注有灯、程序输出 `none` 的帧占比 |
| 误检率 | 标注 `none`、程序输出有灯的帧占比 |
| 分段结果 | **每段单独一行**，测试段标出来；调参段与测试段差 >10 个百分点要解释 |

> 这张表是本题的主体交付物。没有它，检测效果再好也只能拿一半分。

### 2.5 失效分析

**≥5 条**，每条四行：

```
### 失效 N：<一句话现象>
- 复现方法：哪一段视频的哪一秒，怎么稳定触发
- 原因：原理层（如"红色通道与白色背景的饱和度差 < 阈值"）
- 出现次数：在你自己的数据里出现几次 / 影响多少帧
- 可能的改进方向：（选做）
```

可参考方向：同色干扰物（尾灯、招牌）、白色高光、雨夜反光、运动模糊、失焦、
白平衡偏移、两盏灯同时亮、HDR 过曝、镜头脏污、夜间 ISO 噪声。

## 4. 交付物与格式

### 4.1 目录结构

```
M2-1/
├── camera_calibration.yaml      # 标定结果
├── data/
│   ├── raw/                     # 原始视频 ≥3 段（可给网盘链接 + 校验码）
│   ├── labels/                  # 每段一个 json（§4.3）
│   └── frames/                  # 抽出的帧（至少留测试段）
├── calib_imgs/                  # 标定用原图 ≥15 张
├── src/
│   ├── calib.py                 # 标定
│   ├── detect.py                # 检测（单图/视频/摄像头）
│   └── eval.py                  # 评估，输出 eval.csv
├── results/
│   ├── eval.csv
│   └── <段名>/annotated_*.png   # 每段 ≥2 张标注图
├── report.md                    # 标定说明 + 评估表 + 失效情况
└── README.md                    # 一句话能跑起来的三条命令
```

### 4.2 `camera_calibration.yaml` 格式

```yaml
camera:
  model: pinhole
  resolution: [1280, 720]        # 标定时的分辨率（重要！内参与分辨率绑定）
  intrinsics:
    fx: 0.0
    fy: 0.0
    cx: 0.0
    cy: 0.0
  distortion:
    k1: 0.0
    k2: 0.0
    p1: 0.0
    p2: 0.0
    k3: 0.0
  reprojection_error: 0.0        # px
  calib_board:
    type: chessboard
    inner_corners: [9, 6]
    square_size_mm: 0.0          # 实测值
    display: print               # print | screen
  images_used: 18
```

> `resolution` 必填。换分辨率后内参要按比例换算，
> 这是最常见的"标定对了但用的时候错"的原因。

### 4.3 `data/labels/*.json` 格式

```json
{
  "video": "day_01.mp4",
  "fps": 30,
  "frames": [
    {"frame": 120, "t": 4.00, "state": "red",    "center": [640, 360], "radius_px": 28},
    {"frame": 123, "t": 4.10, "state": "none",   "center": null,       "radius_px": null}
  ]
}
```

`state` 只能取 `red` / `yellow` / `green` / `none`；`none` 时 `center` 与 `radius_px` 为 `null`。

### 4.4 运行约定

```bash
# 标定
python3 src/calib.py --images calib_imgs/ --out camera_calibration.yaml

# 检测：单图 / 视频 / 摄像头 三选一
python3 src/detect.py --image xxx.png --calib camera_calibration.yaml --show
python3 src/detect.py --video data/raw/day_01.mp4 --calib camera_calibration.yaml

# 评估：出 eval.csv
python3 src/eval.py --labels data/labels --pred results/pred --out results/eval.csv
```

参数名可以不同，但**必须能从命令行拿到图像来源**，不允许把路径写死在代码里。

## 5. 明确禁止

- 禁止深度学习/任何预训练模型（这是 M2-3 的题）

- 禁止只交"效果好看"的截图、不给失败样本与失败次数
- 禁止文档与代码矛盾（阈值、内参、光照条件对不上）
