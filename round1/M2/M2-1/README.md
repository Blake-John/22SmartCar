# M2-1 ｜ 传统视觉管线：从"能用"到"说得清边界"

> **难度**：★
> **综合考察**：OpenCV 核心操作、色彩空间、阈值/形态学、轮廓检测、相机标定、参数工程
> **本题分值**：10 分
> **题目来源**：`创意组一轮考核.md` §M2-1
> **形式**：自备相机，自行采集数据；现场带代码与文档，现场实测

---

## 0. 这道题在考什么

比赛里最基础的能力：**给你一个能跑的视觉方案，你能说清它的边界在哪里**。
"在光照好的实验室能检测到"不算本事——**知道它什么时候会失效、为什么失效**才算。

因此本题不只看检测结果，更看你：

1. 有没有一套**可复现的标定与检测流程**（而不是一坨调好的魔数）
2. 有没有**实测过**不同光照下的表现（而不是只测了办公桌上一盏灯）
3. 能不能**讲清楚失效原因**（原理层，不是"效果不好就调参"）

## 1. 硬性要求

| # | 要求 | 说明 |
| :-- | :-- | :-- |
| 1 | **只用传统视觉方法** | OpenCV / NumPy。**禁止**深度学习、禁止调用现成的"红绿灯检测"库 |
| 2 | **自备相机** | 笔记本摄像头 / USB 摄像头 / 手机（可作网络摄像头）均可，**必须与标定用同一台** |
| 2b | **自备灯箱与标定板** | 灯箱、棋盘格都**自己解决**（现场不提供）；**灯箱必须带到现场**用于实测 |
| 3 | **输出三项** | 亮灯状态（红/黄/绿）、亮灯中心像素坐标、面积（或半径） |
| 4 | **画出最小外接圆** | 在结果图上，颜色与线宽自定，但要能看清 |
| 5 | **文档 ≥5 种失效情况** | 每条要有**现象 + 原因**，不接受"光照不好"这种一句话 |

## 2. 任务分解

### 2.1 相机标定

**自己采、自己标**，不接受直接写死一组网上抄的内参。

| 步骤 | 要求 |
| :-- | :-- |
| ① 标定板 | 棋盘格（推荐 9×6 **内角点**）。**自己打印**（普通 A4 即可）。打印后**必须用卡尺/直尺量方格边长**（mm），把量到的值写进文档 |
| ② 采集 | **15~20 张**，不同角度、不同距离、覆盖画面**四角与中心**。倾斜不要超过 ~45°，否则角点提取失败率高 |
| ③ 标定 | `cv2.calibrateCamera`。得到内参 (fx, fy, cx, cy) 与畸变 (k1, k2, p1, p2) |
| ④ 质检 | 报告**重投影误差**（RMSE）。**> 0.5 px 要解释原因**；> 1.5 px 视为标定失败，需要重采 |
| ⑤ 保存 | `camera_calibration.yaml`，格式见 §5.2。**M2-2 会直接读这份文件** |

**自检清单**（标完先自查，现场会问）：

- [ ] 换一张**未参与标定**的棋盘图，用你的内参解算位姿并重投影，误差仍然小吗？
- [ ] fx 与 fy 接近吗？（正常相机应接近相等，差很多说明角点检测出了问题）
- [ ] 畸变系数 k1 的符号和量级合理吗？（普通 USB 相机 k1 常为负，量级 -0.3 ~ -0.05）
- [ ] 标定板是否平整？（贴在纸板上，别拿软纸）

> **为什么强调重投影误差**：这是标定是否可信的**唯一客观指标**。
> 报不出这个数，等于没标定。

### 2.2 红绿灯检测

**场景自建（自己解决，现场不提供）**：搭一个灯箱，三盏**竖排**（红/黄/绿），每次**只亮一盏**。
可以用真实 LED、彩色小灯、甚至手机屏幕显示色块——但**三盏要同尺寸、竖排、间距均匀**。
灯箱**必须带去现场**，因为现场实测要用它。

**处理流程**（顺序不可颠倒，每一步都要在文档里说明为什么）：

```
采图 → 去噪 → 颜色分割 → 形态学清理 → 轮廓查找 → 形状/面积过滤
     → 状态判定 → 最小外接圆 → 标注输出
```

| 环节 | 必须说清的问题 |
| :-- | :-- |
| 颜色分割 | 用 HSV 还是 RGB？**为什么**？阈值是多少、怎么定的？ |
| 形态学 | 用了开/闭/腐蚀的哪几种？核多大？解决什么问题？ |
| 过滤 | 面积上下限怎么定？只靠颜色够吗——**同色干扰物**怎么排除？ |
| 状态判定 | 如果两个掩码同时命中怎么办？如果**全都没命中**怎么办（必须输出"未识别"，不许崩） |

**现场实测**：用**你自己搭的灯箱**（必须带到现场）跑一遍、报结果。
**代码必须能读一张图/一段视频就出结果**，不允许现场改代码才能跑。

### 2.3 鲁棒性实测

**至少四种光照**，每种都要**留图、留数据**：

| 光照 | 怎么造 |
| :-- | :-- |
| 正常室内光 | 基准 |
| 强光直射 | 台灯正对灯箱（饱和度会被压低，颜色变淡） |
| 逆光/背光 | 灯后打强光，相机对着光源方向 |
| 暗光/黄昏 | 拉窗帘，只留弱光 |

每种的输出物：**标注图 ×2 + 命中率统计表**（每光照 ≥10 次检测，统计状态正确率、中心误差）。

> 提示：黄昏的暖色偏会把红灯色相从 0° 推向 ~30°。
> 如果你的方案在 dusk 下翻了，先去看**失败样本在 HSV 空间里到底落哪了**，
> 再决定是调阈值、换判据，还是加形状约束——**不要盲调**。

### 2.4 文档：失效情况

**≥5 条**，每条格式：

```
### 失效 N：<一句话现象>
- 复现方法：怎么做能稳定触发
- 原因：为什么（原理层，如"红色通道与白色背景的饱和度差 < 阈值"）
- 现有方案的表现：漏检 / 误检 / 崩溃
- 可能的改进方向：（写不写均可，但写了加分）
```

可参考方向（不限于）：同色干扰物、白色高光、灯箱反光、运动模糊、失焦、
白平衡偏移、两盏灯同时亮、HDR 场景、镜头脏污、灯箱倾斜超出平面假设。

| 环节 | 考官做什么 | 时间 |
| :-- | :-- | :--: |

## 4. 交付物与格式

### 5.1 目录结构

```
M2-1/
├── camera_calibration.yaml      # 标定结果
├── detect.py                    # 检测主程序（可读图/视频/摄像头）
├── calib.py                     # 标定脚本（可选，也可并入 detect.py）
├── report.md                    # 标定说明 + 光照对比表 + 失效情况
├── calib_imgs/                  # 标定用原图（≥15 张）
├── results/
│   ├── normal/  annotated_*.png ×2
│   ├── glare/
│   ├── backlight/
│   └── dusk/
└── README.md                    # 运行方式（一句话能跑起来）
```

### 5.2 `camera_calibration.yaml` 格式

```yaml
camera:
  model: pinhole
  resolution: [1280, 720]        # 标定时的分辨率（重要！内参与分辨率绑定）
  intrinsics:
    fx: 0.0
    fy: 0.0
    cx: 0.0
    cy: 0.0
  distortion:
    k1: 0.0
    k2: 0.0
    p1: 0.0
    p2: 0.0
    k3: 0.0
  reprojection_error: 0.0        # px
  calib_board:
    type: chessboard
    inner_corners: [9, 6]
    square_size_mm: 0.0          # 卡尺量出来的实际值
  images_used: 18
```

> `resolution` 必填。换分辨率后内参要按比例换算，
> 这是最常见的"标定对了但用的时候错"的原因。

### 5.3 运行约定

```bash
# 标定
python3 calib.py --images calib_imgs/ --out camera_calibration.yaml

# 检测：单图 / 视频 / 摄像头 三选一，必须都支持读文件
python3 detect.py --image xxx.png --calib camera_calibration.yaml --show
python3 detect.py --video xxx.mp4 --calib camera_calibration.yaml
```

参数名可以不同，但**必须能从命令行拿到图像来源**，不允许把路径写死在代码里。
