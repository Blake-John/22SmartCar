# M2-4 ｜ 目标追踪与运动预测：从"检测到"到"跟得住"

> **难度**：★★★★
> **综合考察**：多目标跟踪（ID 保持）、卡尔曼滤波、遮挡处理、运动预测、工程综合
> **本题分值**：40 分
> **题目来源**：`创意组一轮考核.md` §M2-4
> **形式**：自备视频素材；现场带代码与文档实测（考官会用遮挡物现场造一次遮挡）
> **耦合**：**直接使用 M2-3 的检测器**做输入——本题与 M2-3 是同一条链路

---

## 0. 这道题在考什么

检测器每帧独立输出，**它不知道上一帧发生了什么**。追踪要补的正是这一层记忆：

- 同一个物理目标，跨帧必须拿到**同一个 ID**
- 目标被遮挡 10 帧，ID 不能丢、位置还得"猜"出来
- 不光知道**现在**在哪，还能预测**接下来**去哪

纯 IoU 匹配有两个致命伤（题面原文，也是本题的立意）：

1. **检测框有噪声**——YOLO 每帧输出的框会轻微抖动，直接拿来当位置，ID 容易在相邻目标间跳变
2. **遮挡时没有检测可用**——没有任何输出可匹配，目标就被删了，再出现时拿了个新 ID

这两条你要能**用自己跑出来的数据证明**：先写个纯 IoU 版本，
统计"ID 切换次数"，再上卡尔曼，对比数字——**这是本题最有说服力的交付**。

## 1. 硬性要求

| # | 要求 | 说明 |
| :-- | :-- | :-- |
| 1 | **输入** | M2-3 检测器的逐帧输出（类别、置信度、bbox）。现场可用录好的检测序列 JSON 或实时跑 |
| 2 | **ID 保持** | 同一目标跨帧同 ID；**同类别不同目标不同 ID**；目标离开画面后 ID 不复用 |
| 3 | **累计位移** | 从进入画面到当前位置的**像素位移**，实时显示 |
| 4 | **轨迹** | 在画面上画出每个 ID 的运动轨迹（尾迹长度自定，要能看清） |
| 5 | **卡尔曼滤波** | 至少对中心点做恒速（CV）模型；**必须解释为什么**（见 §0） |
| 6 | **短时遮挡预测** | 未匹配到检测时**不立即删除**，改用预测值继续输出；**虚线框**表示"这是预测"；连续预测 **≤10 帧**，超过才删；重新出现时**用新检测更新**并**保持原 ID** |
| 7 | **运动估计** | 预测目标下一帧位置（输出预测框，与当前框用颜色/线型区分） |

## 2. 任务分解

### 2.1 追踪与 ID 管理

**数据关联**建议：IoU 代价矩阵 + **匈牙利算法**（`scipy.optimize.linear_sum_assignment` 或手写），
而不是逐个贪心——贪心在目标交叉时会锁错。

**必须想清楚并写进文档**：

| 问题 | 要给出你的策略 |
| :-- | :-- |
| 匹配阈值 | IoU 低于多少算"没匹配上"？定高了会提前删轨迹，定低了会张冠李戴 |
| 新目标诞生 | 什么条件下给新 ID？（连续 N 帧命中才给，还是首帧就给？——抖动检测会刷出假目标） |
| 老目标死亡 | 连续多少帧无匹配才删？与 §2.3 的 10 帧预测如何衔接 |
| 置信度 | 低置信度检测要不要参与匹配？（高置信度优先的两级匹配是常见做法） |
| 类别 | 类别不一致的目标能匹配吗？（一般不能；但检测类别抖动时怎么办） |

**ID 复用是硬伤**：目标 A 出画，它的 ID 被新目标顶上——这在演示里一眼就能看出来，
现场会专门用"出画再入"的片段考这一点。

### 2.2 卡尔曼滤波

| 项 | 要求 |
| :-- | :-- |
| 状态量 | 至少 `[cx, cy, vx, vy]`；建议 `[cx, cy, w, h, vx, vy]`（框尺寸也做平滑） |
| 过程噪声 Q | 说明怎么定的（与目标**加速度**的不确定性相关），拍脑袋值要说出量级依据 |
| 观测噪声 R | 与检测框抖动的**实测方差**挂钩——**用数据定，不是拍脑袋**（见下） |
| 融合方式 | 有检测时"预测+更新"；无检测时只"预测"并输出预测框 |

**Q 与 R 必须有依据**，这是滤波部分的核心考点：

- **R 的正确姿势**：让目标**静止不动**录 100 帧，统计检测框中心的抖动方差——这就是 R 的来源
- Q 的量级：目标最快移动速度 × 帧间隔 × 加速的不确定系数
- 现场会问："你的 R 是怎么来的？"——**必须能说出实测方法**（不是"试出来的"）

**必须回答**：

- 为什么不用匀速直线外推就行，非要卡尔曼？
  （答案要点：卡尔曼是**最优融合**——预测与观测各带不确定性加权，
  且能递归计算、给出协方差；纯外推既不融合观测也不给置信度）
- 观测突然不可信（遮挡边缘的框残缺）时，卡尔曼怎么"自动少信它一点"？

### 2.3 短时遮挡预测

| 规则 | 要求 |
| :-- | :-- |
| 0~10 帧 | 无匹配 → 用**预测值**输出，框画**虚线**，ID 保持，画面标注 `PREDICTED` |
| >10 帧 | 删除轨迹 |
| 重现 | 预测期间重新匹配上 → 用**新检测更新**卡尔曼，**ID 不变**，虚线恢复实线 |

**必须实测**（写进文档，现场会演）：

| 实验 | 做法 | 指标 |
| :-- | :-- | :-- |
| 遮挡恢复率 | 人工制造 5 / 10 / 15 / 20 帧遮挡（贴纸挡住或剪辑掉检测） | 各档位的 ID 保持率 |
| 预测误差 | 遮挡期间，预测框 vs 真实位置的像素误差随帧数的曲线 | 画曲线，说明第几帧开始"预测不可信" |
| 10 帧阈值 | 为什么是 10 帧？改成 5 帧/20 帧各会怎样？ | 给出你实测的权衡 |

> **10 帧不是拍脑袋**：匀速模型下预测误差随帧数**二次增长**，
> 10 帧（约 0.3~0.4s）通常是"还能预测"与"纯属瞎猜"的分界。
> 你要用自己的数据画出这条误差曲线来支撑。

### 2.4 运动估计

- 输出**下一帧**的预测框（与当前框视觉区分）
- 若目标有明确运动模式（直线、转弯、往返），演示预测的合理性
- **加分项**（择一即可）：
  - 用 **CTRV/CTRA**（恒转弯率）模型替换 CV，对转弯目标明显更稳，给出对比数据
  - 预测置信度可视化：协方差大 → 框的颜色/透明度变化

## 3. 素材（硬性要求）

**自备一段 ≥30 秒视频**，必须包含以下**全部**情节。
**缺哪个情节，考官就无法验证对应能力**：

| 情节 | 时长 | 考什么 | 缺失扣在哪一项 |
| :-- | :-- | :-- | :-- |
| 多目标并行 | ≥5s | ID 分配 | ID 管理与关联 −3 |
| 两目标**交叉**换位 | ≥3s | 关联是否锁错 | ID 管理与关联 −4 |
| 短时**遮挡**（5~10 帧） | ≥2 次 | 预测与 ID 保持 | 遮挡预测 −6 |
| 目标**出画再入** | ≥1 次 | ID 不复用 | ID 管理与关联 −3 |
| 静止目标 | ≥5s | 滤波降噪效果 | 卡尔曼滤波 −3 |

> 素材是本题的**前提**：没有对应情节，考官就无法验证你的实现，
> 那些判据只能记 0。**自己负责把情节拍全**。

- 用 M2-3 检测器跑出逐帧检测（JSON 存档），追踪代码**既能读 JSON 也能接实时检测**

## 6. 检测输入接口

```python
# detections/*.json 结构（M2-3 的输出约定）
{
  "video": "my_scene.mp4",
  "fps": 30,
  "classes": ["class_0", "...", "class_5"],
  "frames": [
    {"frame": 0, "dets": [
        {"cls": 3, "conf": 0.87, "bbox": [x1, y1, x2, y2]},
        ...
    ]},
    ...
  ]
}
```

> **为什么提供 JSON 通道**：让你能把"检测"与"追踪"**分开调试**——
> 追踪的效果不该被检测质量裹挟。但**最终演示必须接 M2-3 实时检测**，
> 现场会核对。
